### Bugs found and fixed during verification
1. Lightbox image overflowed its row — a centred grid item sizes to intrinsic height, so
   `max-height:100%` never resolved. Now absolutely positioned against a definite box.
2. **Page stayed scroll-locked after closing the lightbox** — cleanup was tied to the
   `<dialog>` `close` event, which was not delivered. Cleanup is now explicit and idempotent.
3. Horizontal scroll at 320 px — header brand + labelled menu button didn't fit. Brand now
   shrinks/ellipses and the button goes icon-only below 400 px.
4. White-on-LINE-green was 2.25:1. Button green darkened to `#05852F` (**4.77:1**); the true
   brand `#06C755` is kept for the icon chip tint.
5. Footer `h4` after `h2` broke heading order → now `h3`.
6. Gallery `alt` duplicated the visible caption → `alt=""` (button carries the name).
7. Mobile call bar wasn't in a landmark → now `<nav>`.
8. Header logo link failed WCAG 2.5.3 (Label in Name): its `aria-label` didn't contain the
   visible text. `aria-label` removed so the visible text *is* the name.
9. `<img src="">` in the lightbox fired a bogus request for the page itself → `src` removed.
10. Google Fonts cost ~0.9 s of blocked render (LCP 3.8 s) → fonts self-hosted; hero gained a
    760 w `srcset` variant so phones fetch 36 KB instead of 67 KB.

### Known/accepted
- Opening `index.html` by **double-click (`file://`)** logs two harmless CORS errors for the
  two `rel="preload"` font hints (`crossorigin` is required for font preloads over http but
  rejected on `file://`). **The fonts still load and render correctly.** Serving over
  Live Server / any http server — the normal workflow — produces no errors.
- CSS/JS are unminified on purpose: this is a hand-editable handover file. Gzip takes the
  page from 89 KB to **19 KB** on the wire.

### Bugs found and fixed while porting
1. **A fast flick could strand content invisible forever.** `onScroll` can miss an element that
   crosses from below the viewport to above it inside one scroll event, leaving it at
   `opacity:0`. The play-once reveals now use a rAF-throttled "top edge has crossed the line"
   check that is still true after you have scrolled past, so it cannot be skipped at any speed.
   (`onScroll({sync:0.35})` is kept for parallax, where scrubbing is the point.)
2. `utils.cleanInlineStyles(el)` takes an **animation**, not an element — it threw
   `s.pause is not a function` on every reveal, and would have wiped the reveal anyway.
3. The hero photo was hidden by `.js [data-hero]{opacity:0}` while its arrival animates
   transform only — it is the LCP node, so it is now excluded from the hiding rule.
4. Reveal's left/right variants start 40px outside the viewport → horizontal scroll on mobile.
   Fixed with `overflow-x:clip` on `html` (`hidden` would have broken the sticky header).
5. `.img-zoom`'s `overflow:hidden` clipped the PhotoFrame brackets; the zoom now clips on an
   inner `.hm-clip` wrapper.
6. Thai stacks vowels/tone marks above and below the baseline — splitText's `overflow:clip`
   word box shaved them off until it was given vertical padding.
7. A re-split on resize re-hid already-revealed words; the fresh word set now jumps to its
   resting state.
8. splitText reverts and recreates its observer on re-split, so refreshing every observer on
   `load` crashed at 320px. Only parallax observers are refreshed now.
9. Dropped **Anuphan Latin (68 KB)** — the display font is now Thai-only and Latin digits fall
   through to the body face. Those late-swapping faces were moving the hero and were the whole
   of a 0.22 CLS regression.

## Cream theme (2026-08-04)

Done purely at the **primitive token** level — no component CSS was touched, which is the
test Step 2 of the skill sets ("you could restyle the whole site by editing only tokens").

- Neutral ramp: hue 255 (cool blue-grey) → **hue ~83 (warm cream)**. **Every lightness value
  was kept identical**, so all text/background contrast ratios carry over unchanged.
- Shadows re-hued 255 → 70, so they read as shade on cream instead of a blue haze.
- Aurora re-mixed amber-led (was navy-led) and dropped from `.5` to `.30` opacity; the static
  hero gradients halved. At full strength the hero went orange rather than *white-ish* cream.
- Brand navy **kept** — it is taken from the logo, and it is what keeps the cream reading as a
  deliberate choice rather than undyed beige.
- Dark mode inherits the warm neutrals, so it is now espresso rather than blue-black.

Contrast recomputed from the OKLCH tokens (exact, not sampled). Worst text pair **5.09:1**
(dark action label on the light-blue action fill); everything else 6.3 – 18.8:1. axe: **0
violations** in both schemes.

### Dark mode removed (2026-08-04)

**The site is cream for every visitor**, regardless of their OS setting. Removed:

- the whole `@media (prefers-color-scheme: dark)` semantic-token block;
- `color-scheme: light dark` → **`color-scheme: light`**, so the browser also keeps form
  controls, scrollbars and autofill light — without this the UA still paints native widgets
  dark and they clash with the cream page;
- three scattered dark-only overrides (`.eyebrow`, `.area-list .pin`, `.aur-pool` opacity);
- the `.map-frame iframe` invert/hue-rotate filter, which existed only to tint Google's map
  tiles for the dark palette. Google's normal light tiles now match the cream card.

Verified: with the OS forced to dark, `body` background is still `oklch(.995 .009 85)` and
`color-scheme` computes to `light`. `prefers-color-scheme` appears **0 times** in the file.

## Gallery: why exactly 12 photos

The gallery used to be 11 photos with three `grid-row: span 2` "tall" cells = 14 cells. 14
doesn't divide by 4, so the final row was left with an L-shaped hole (two empty cells beside a
tall one). Packing with `grid-auto-flow: dense` moved the hole around but couldn't remove it —
with span-2 cells the tail is ragged for *some* column count no matter what.

Fix: uniform cells, and a photo count divisible by **every** column count this grid produces.
`repeat(auto-fill, minmax(min(100%,15rem),1fr))` inside a 1180px wrap yields **4 / 3 / 2 / 1**
columns, and **12** is divisible by all four. Verified — last row is full at 390 / 560 / 768 /
900 / 1024 / 1280 / 1440 / 1920 px.

**If you add or remove photos, keep the total at 12 or 24**, or the hole comes back at one of
those widths.
