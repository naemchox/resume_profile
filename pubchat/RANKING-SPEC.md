## 1. หลักการที่ห้ามละเมิด (invariants)

1. **เงินซื้อ "ชั้นสมาชิก" ได้ · เงินซื้อ "คะแนนพฤติกรรม" ไม่ได้เด็ดขาด**
   ถ้าเงินขยับคะแนนแล้วข้อมูลหลุด = ขายการเข้าถึงคนที่ไม่ได้ยินยอมให้ถูกประมูล → แบรนด์ตาย
   (เคสอ้างอิง: Tinder ELO ที่โดนต่อต้านหนักตอนถูกเปิดเผย)
2. **ไม่โชว์คะแนนให้ใครเห็น** — ทั้งของตัวเองและของคนอื่น สมาชิกเห็นได้แค่ *สถิติของตัวเอง*
   ("คุณมาตามนัด 92%") ห้ามมีตัวเลข rank/เกรด/ดาว ปรากฏใน UI
3. **คำขายพูดถึงพฤติกรรม ไม่ใช่หน้าตา** — "ที่นี่คุณจะเจอแต่คนที่มาตามนัดจริง"
   ห้ามสื่อว่า "จัดระดับความน่าคบ/ความสวย" (พูดออกสื่อได้ = ปลอดภัยเวลาหลุด)
4. **จับคู่ข้ามชั้นได้ไม่เกิน ±1 tier**
5. **เครดิต "เจอจริง" ต้องยืนยัน 2 ฝ่าย** ผ่าน QR handshake เท่านั้น — ไม่มีการกดยืนยันฝ่ายเดียว

## 2. ชั้นที่ 1 — Membership class (เปิดเผยได้ ขายตรงได้)

| ชั้น | ราคา (เสนอ) | ได้อะไร | เข้าได้เมื่อ |
|---|---|---|---|
| **Free** (ค่าเริ่มต้น) | ฿0 | เข้า pool ทันที · **คำเชิญ 1 คน/สัปดาห์** · นัดเจอ+ยืนยันการเจอครบ | สมัครเสร็จได้เลย |
| **Verified** | ฿2,900 / 3 เดือน | คำเชิญ 3/สัปดาห์ | กด "อัปเกรด" + ชำระเงิน |
| **Circle** | ฿9,900 / แพ็ก 3 นัด | + concierge จัดคู่ให้ด้วยมือ, จัดตารางนัด, คำเชิญ 8/สัปดาห์ | ชำระเงิน |
| **Inner** | ฿25,000 / 6 เดือน | + priority slot, จัดนัดแบบ private, คำเชิญไม่จำกัด | ชำระเงิน (ยืนยันอาชีพ/รายได้ = ทางเลือก ไม่บังคับ) |

- **ตัวคุมสัดส่วนเพศคือ "ราคา" ไม่ใช่ "การคัด"** (ตัดสิน 17 ส.ค.): ยังไงฝั่งชายก็สมัครมากกว่าตามธรรมชาติ การอ่านใบสมัครไม่ได้ทำให้สัดส่วนดีขึ้นเลย → ฝั่งที่ขาด (ปกติคือฝั่งหญิง) เข้าราคาต่ำกว่าหรือฟรีในช่วง seeding ประกาศเปิดเผยได้ ไม่ใช่ความลับ
- ทุกคนในชั้นเดียวกันจ่ายเท่ากัน = แฟร์แบบชั้นที่นั่งเครื่องบิน จึงประกาศได้เต็มปากว่า "เจอกันในชั้นเดียวกัน"

**จุดขายอัปเกรด = ตอนคำเชิญหมด (18 ส.ค.)** — โควตาคำเชิญคือสิ่งเดียวที่ `plan` เปลี่ยนจริงในโค้ด (ตรวจแล้ว: `plan` ถูกอ่านที่ `inviteQuota` ที่เดียว) เดิมตอนหมดโควตาขึ้นแค่ toast "หมดแล้ว" = บอกว่าไม่ได้ แล้วจบ ตอนนี้ขึ้น sheet ที่บอก 2 อย่างที่จริง: **คำเชิญฟรีกลับมาวันจันทร์ไหน** และ **ชั้นถัดไปราคาเท่าไหร่ได้กี่คำเชิญ** · ปุ่มที่สอง = "ไว้สัปดาห์หน้า" (ไม่บังคับ ไม่ปิดของที่มีอยู่) · เข้าได้อีกทางจากการแตะ pill คำเชิญตอนเหลือ 0
- ยังไม่ได้ทำ (ตั้งใจ): ไม่มี "ใครสนใจคุณ" ให้ขาย เพราะคำเชิญ = เปิดห้องแชททันที ทั้งสองฝั่งเห็นกันอยู่แล้ว — ถ้าจะขายของแบบนั้นต้องเปลี่ยนกลไกคำเชิญเป็น 2 จังหวะก่อน

## 3. ชั้นที่ 2 — คะแนนที่มองไม่เห็น (Trust & Conduct Score)

คะแนนรวม 0-100 (+ โทษติดลบไม่จำกัด) เก็บที่ `users/{uid}.tcs` **เขียนได้จาก server เท่านั้น**

| รหัส | สัญญาณ | เต็ม | สูตร | เงินซื้อได้ |
|---|---|---|---|---|
| S1 | ความลึกของการยืนยันตัวตน | 30 | ID+liveness = 15 · อาชีพ/การศึกษา = +8 · รายได้/เอกสาร = +7 | 🟡 จ่ายค่าตรวจได้ แต่ปลอมไม่ได้ |
| S2 | **Show-up rate** | 30 | `30 × (นัดที่ประทับครบ 2 ฝ่าย ÷ นัดที่**ตอบรับแล้ว**และเลยเวลา)` ขั้นต่ำ 3 นัดจึงเริ่มนับ — นัดที่อีกฝ่ายไม่เคยตอบ **ไม่นับ** (ไม่งั้นใครก็ยิงนัดทิ้งเพื่อทุบสถิติเราได้) | ❌ |
| S3 | Reciprocity | 20 | `20 × (คำเชิญที่ถูกตอบรับ ÷ คำเชิญที่ส่ง)` — สิทธิ์ส่งจำกัดต่อสัปดาห์ กันยิงมั่ว | ❌ |
| S4 | คุณภาพการสนทนา | 20 | ตอบภายใน 24 ชม. = 10 · บทสนทนา ≥10 ข้อความ = 6 · ไม่ ghost หลังนัด = 4 | ❌ |
| P | **โทษ** | −∞ | no-show −25/ครั้ง · ถูกรายงานและตรวจแล้วจริง −40 · ถูกบล็อกซ้ำ ≥3 คนใน 30 วัน −30 | ❌ |

**tier จากคะแนน:** T1 <25 · T2 25-44 · T3 45-64 · T4 65-84 · T5 ≥85
`P ≤ −40` → **suspend** ออกจาก pool ทันที รอรีวิวมือ

### กฎกันโกง (ต้องมีตั้งแต่วันแรก)
- **provisional**: สมาชิกใหม่ 60 วันแรก / ก่อนครบ 3 นัด → tier = T3 คงที่ จับคู่ได้เฉพาะ provisional และ ±1
- **decay**: กิจกรรมเก่ากว่า 90 วัน ถ่วงน้ำหนัก 0.5 · เก่ากว่า 180 วัน = 0 → หายไปนานกลับมาต้องพิสูจน์ใหม่
- **กันฟาร์ม meet credit**: QR ต้องสแกน 2 ฝ่าย + คู่เดิมนับได้ครั้งเดียวต่อ 30 วัน + ต้องมีนัดที่บันทึกไว้ก่อนล่วงหน้า ≥2 ชม.
- **กันปั่น S3**: สิทธิ์ส่งคำเชิญจำกัดตามชั้นสมาชิก (3/8/ไม่จำกัดแบบ concierge) — ส่งเยอะไม่ได้ = ปั่นอัตราตอบรับไม่ได้
- **ห้ามคำนวณ tcs ที่ client** — client ที่แก้ค่าได้ = คะแนนไร้ความหมาย (ดูข้อ 6)

## 4. Admission flow (ของจริงที่ต้องเขียน)

```
สมัคร (onboarding) → [active, Free] → ใช้แอปได้เลย
   ↘ กด "อัปเกรด" ในแท็บตัวฉัน → กรอกฟอร์ม → เราแจ้งยอด → เงินเข้า → operator ตั้ง `plan`
ไม่มีขั้นคัด ไม่มีการกั้นก่อนจ่าย — `status` เหลือหน้าที่เดียว: suspended / banned / expired
→ [active, provisional 60 วัน] → เข้า pool → รับคำเชิญ/ถูกจัดคู่
→ นัด (มีเวลา+สถานที่สาธารณะ) → เจอจริง → สแกน QR 2 ฝ่าย → เครดิต S2
```
สถานะบน `users/{uid}.status`: `pending` · `active` · `suspended` · `banned` · `expired`
ทุก state ที่ไม่ใช่ `active` = ไม่ปรากฏใน pool และอ่าน presence คนอื่นไม่ได้

## 6. ข้อจำกัดทางเทคนิคที่ต้องยอมรับ

- `tcs`/`tier`/`status` **เขียนจาก client ไม่ได้** → ต้องมี Cloud Function = **ต้องขึ้น Blaze** (⚠️ `functions/` ที่มีอยู่คือโค้ดเหรียญ/Stripe ของโมเดลเก่า **ไม่ใช่โครงของคลับ** — ย้ายเป็น `_legacy-coins.index.js.bak` แล้ว ดู `functions/README.md`; Function ของคลับต้องเขียนใหม่ทั้งหมด) (Spark deploy functions ไม่ได้ และ presence 12 วิ/คน ชนเพดาน Spark ตั้งแต่คนที่ 3-6 ที่ออนไลน์ 8 ชม.)
- P1 ยังไม่ต้องมี Function: สถานะสมาชิก/การ verify แก้ผ่าน Firebase Console ด้วยมือได้ (30 คนแรก)
- **ไม่มีการคัดกรอง/สัมภาษณ์แล้ว** (ตัดออก 17 ส.ค.) → ประหยัดค่า liveness ฿47-67/คน + ค่าขั้นต่ำ $135-325/เดือน และประหยัดเวลา operator ทั้งหมด. แลกกับ: **แอปห้ามอ้างว่ารับรองความปลอดภัยหรือรับรองตัวตนของใคร** (หน้าเงื่อนไขในแอปเขียนตรงแล้วว่า "สมาชิกมาจากการชำระเงิน ไม่ใช่การรับรองความปลอดภัย") ถ้าจะกลับมาทำ verify ให้ทำเป็น **ทางเลือกที่ให้แต้ม S1** ไม่ใช่ด่านบังคับ

  - แก้ทีหลังได้: `openMatchPrefs()` เข้าจากหน้าแก้โปรไฟล์ → บันทึกแล้ว `writePresence()` ทันที
  - โปรไฟล์/ป๊อปอัปโชว์แค่ **ตัวตน** ไม่โชว์ว่าคนนั้นอยากเจอใคร (ไม่ต้องเปิดเผยรสนิยมของเขาให้คนอื่น)
  - ตรวจตรรกะแล้วด้วย truth table: ชายที่เลือก "ผู้หญิง" → เห็นผู้หญิงที่เลือกผู้ชาย ✓ · **ไม่เห็น**ทรานส์หญิง/นอนไบนารี ✓ · ไม่เห็นผู้หญิงที่เลือกเฉพาะผู้หญิง ✓
- **ล้าง economy ที่ค้าง**: `openCoinShop`/`openRewards`/`startCheckout` **ไม่มี call site อยู่แล้ว** (grep ยืนยัน ไม่ใช่เดา) → ทำเครื่องหมาย DEAD ห้ามต่อสายกลับ · ถอด `regenFreeBalls()` ออกจาก boot (เขียน Firestore ทิ้งทุกครั้งที่เปิดแอปโดยไม่มีใครอ่าน) · เลิกเขียน `coins/freeBalls/paidBalls` ตอนสร้างโปรไฟล์ · ถอด `handleCheckoutReturn()` ออกจาก boot (toast บอก "เหรียญจะเข้า" = ผิดโมเดล)

**ข้อจำกัดที่รู้ตัว (อย่าเคลมเกิน):**
- **QR ไม่ใช่ความลับ** — ทั้งสองฝ่ายรู้ meet id อยู่แล้ว ดังนั้นตัว QR พิสูจน์ความใกล้ไม่ได้เอง
  สิ่งที่พิสูจน์คือ **"ยืนยันพร้อมกัน"** → rules บังคับให้ confirm ที่สองต้องเข้ามา **ภายใน 15 นาที** จากอันแรก
- **พิกัดไม่ได้บังคับใน rules** (GPS ในตึกพังบ่อย ถ้าบล็อกจะลงโทษคนที่เจอกันจริง) → เก็บไว้ให้ชั้นคิดคะแนนตัดสิน
- **"คู่เดิมนับได้ครั้งเดียว/30 วัน" ยังบังคับไม่ได้** ต้องมี Cloud Function (Blaze) — ชั้นคิดคะแนนต้องกรองเอง
- **โควตาคำเชิญไม่ได้ถูกบังคับจริง** — ตัวนับอยู่บน `users/{uid}.inviteWeek` ซึ่งเจ้าตัวแก้ได้ (rules นับ write ไม่ได้ ต้องใช้ Function) → ห้ามพูดว่า "บังคับแล้ว" กับสมาชิก
- **ยังไม่ทดสอบกับ Firebase จริง และยังไม่มี test ของ rules เลย** — ที่ผ่านมา = `node --check` + อ่านตรรกะด้วยตา + QC รันด้วย Playwright WebKit บน**สตับ** Firebase ที่เขียนเลียน rules (ไม่ใช่ emulator ไม่ใช่ Firestore จริง)

## 6.6 Ops runbook — รับสมาชิกด้วยมือ (P1)

ทุก field ที่ตัดสินสิทธิ์เป็น server-owned: **client แก้ไม่ได้** ต้องแก้ใน Firebase Console

0. **ก่อนเปิดรับสมาชิก:** ไล่ดู `users` ทุกใบที่**ไม่มี field `status`** (บัญชียุคแอปฟรี) — ตอนนี้ถูกตีเป็น `pending` แล้วโดยค่าเริ่มต้น ถ้าอยากให้ใครใช้ต่อ ต้องตั้ง `status:'active'` + `plan` เอง และเติม `gender`/`seek` ให้ (ไม่มี = เห็นทุกคน/ทุกคนเห็น) พร้อม `sensitiveConsentAt` ถ้าจะอ้างความยินยอมตาม ม.26
1. มีใบสมัครใหม่ → Console → Firestore → `users` → หาคนที่ `status == 'pending'` → อ่าน `application` (อายุ/เมือง/งาน/สิ่งที่มองหา/ช่องทางติดต่อ/แพ็กที่เลือก)
2. ติดต่อตาม `application.contact` → **แจ้งยอดตามแพ็กที่เขาเลือกไว้** (ไม่ต้องสัมภาษณ์ ไม่ต้องคัด)
3. แจ้งยอดตามแพ็ก → รับเงินผ่านโอน/PromptPay (fee ~0-1.8% ไม่ต้องมีนิติบุคคลเหมือน Stripe)
4. เงินเข้าแล้ว → แก้ 2 field: `plan` = `verified|circle|inner` และ `status` = `active` — **แล้วบอกให้สมาชิกปิดแอปเปิดใหม่** (แอปอ่าน status ครั้งเดียวตอนเข้าระบบ ไม่มี live listener)
   (โควตาคำเชิญผูกกับ `plan` อัตโนมัติ: 3 / 8 / ไม่จำกัด)
5. หมดแพ็ก → `status` = `expired` · โดนรายงานอยู่ระหว่างตรวจ → `suspended` · ตัดถาวร → `banned`
6. รายงานที่สมาชิกกดเข้ามาอยู่ที่ collection `reports` (`status:'open'`) — อ่านได้จาก Console เท่านั้น ไคลเอนต์อ่านไม่ได้
