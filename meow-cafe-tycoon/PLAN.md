# แผนแมพ Meow Meow Café Tycoon 🐱☕

อิงจาก `Meow Meow Café Tycoon.md` (สัปดาห์ 1: สร้างร้านและเคาน์เตอร์ใน Roblox Studio)
สถานะ: **แมพเสร็จ (ขั้นที่ 1–5) ทดสอบใน Studio แล้ว** (5 พ.ย. 2026) — ต่อไปขั้นที่ 6 ระบบเกม · วิธีเปิดดูหัวข้อ 8

## 1. ภาพรวมโลก (6 ช่อง)

```
            [ ร้าน 1 ]   [ ร้าน 2 ]   [ ร้าน 3 ]
                 \           |           /
                  ====  ลานกลาง (Plaza)  ====
                  จุดเกิด · ป้ายโบนัสรายวัน · น้ำพุแมว
                  ====                    ====
                 /           |           \
            [ ร้าน 4 ]   [ ร้าน 5 ]   [ ร้าน 6 ]
```

- เซิร์ฟเวอร์ละ 6 ช่อง (Plot) ผู้เล่น 1 คนได้ 1 ช่อง
- ลานกลางเป็นจุดเกิดและจุดเจอกัน ทุกคนเดินผ่านร้านคนอื่น ทำให้ได้โชว์ร้าน (สูตรข้อ 3)
- ช่องละประมาณ 80×80 studs เว้นระยะกันไว้ ลูกค้าของแต่ละร้านจะได้ไม่เดินชนกัน
- ช่องที่ยังไม่มีเจ้าของจะเป็นพื้นว่าง มีแท่นจองร้าน (`ClaimPad`) ให้เดินไปกดเป็นเจ้าของ
- ขนาดแมพรวมประมาณ 300×200 studs (ลานกลาง + 6 ช่อง)

## 2. ผังร้าน 1 ช่อง

```
  ┌──────────────── ลานด้านนอก ────────────────┐
  │  ป้ายชื่อร้าน + ชื่อเจ้าของ                  │
  │  ┌────────────── ตัวร้าน ──────────────┐    │
  │  │ [กาแฟ] [ขนมปัง] [นมปั่น]  ← สถานี     │    │
  │  │ ════════ เคาน์เตอร์ ════════          │    │
  │  │  Q3  Q2  Q1  ← จุดต่อคิว              │    │
  │  │                                      │    │
  │  │  โต๊ะ1  โต๊ะ2   (โต๊ะ3) (โต๊ะ4) ← ล็อก │    │
  │  │  (โต๊ะ5)(โต๊ะ6)  ← พื้นที่อัปเกรด      │    │
  │  └──────────── ประตู ────────────────┘    │
  │        ↑ เส้นทางลูกค้า (waypoint)           │
  │  จุดเกิดลูกค้า     ตู้อัปเกรด · แท่นจองร้าน │
  └────────────────────────────────────────────┘
```

| โซน | ทำอะไร | หมายเหตุสำหรับขั้นถัดไป |
| --- | --- | --- |
| สถานี 3 จุด | กาแฟ, คุกกี้/ขนมปัง, นมปั่น | เผื่อที่ว่างไว้อีก 2 จุดสำหรับเมนูที่ปลดล็อกทีหลัง |
| เคาน์เตอร์ | ผู้เล่นเสิร์ฟจากหลังเคาน์เตอร์ | ใส่ ProximityPrompt ในสัปดาห์ 1 |
| จุดต่อคิว Q1–Q5 | ลูกค้ายืนรอ | วางเป็น Part ล่องหน เรียงตามลำดับ |
| โต๊ะ 6 ชุด | เปิดใช้ 2 ชุด อีก 4 ชุดล็อกไว้ | ใช้กับอัปเกรด "จำนวนที่นั่ง" ซ่อน/โชว์ได้ |
| เส้นทางลูกค้า | เดินจากจุดเกิด เข้าประตู ไปเข้าคิว แล้วไปโต๊ะ | waypoint ล่องหน ลูกค้าเลื่อนตามจุดด้วย TweenService (ดูข้อ 9.7) |
| ตู้อัปเกรด | ตู้ 1 ตัวข้างเคาน์เตอร์ ใช้ ProximityPrompt (PC กด E, มือถือแตะ, จอยใช้ได้) | กดแล้วเปิดเมนู UI เดียวกับปุ่มบนจอ (ดูหัวข้อ 5) |
| แท่นจองร้าน | ผู้เล่นกดเพื่อเป็นเจ้าของช่อง | ซ่อนหลังจองแล้ว |
| ช่องตกแต่ง | จุดวางของแต่งร้าน | ใช้กับของแต่งที่ขาย (สัปดาห์ 3) |

## 3. หลักการตั้งชื่อ

ทุกร้านใช้โครงสร้างเดียวกัน สคริปต์จะได้หาของเจอโดยไม่ต้องจำพิกัด:

```
Workspace
└─ Plots
   └─ Plot1 … Plot6
      ├─ Building     (ผนัง พื้น หลังคา)
      ├─ Stations     Coffee / Bakery / Shake
      ├─ Counter
      ├─ Queue        Q1 … Q5
      ├─ Seats        Table1 … Table6
      ├─ Path         WP1 … WPn
      ├─ CustomerSpawn
      ├─ UpgradeKiosk
      ├─ ClaimPad
      └─ Sign
```

ทำร้านต้นแบบ 1 ร้านก่อน แล้วโคลนเป็น 6 ช่อง ถ้าแก้ร้านต้นแบบ ทุกร้านก็จะเปลี่ยนตามกัน

## 4. หน้าตา

- ทำจาก Part ธรรมดาทั้งหมด สีพาสเทล (ครีม ชมพู ฟ้าอ่อน และน้ำตาลไม้) ไม่ใช้โมเดลจาก Creator Store (เลี่ยงปัญหาลิขสิทธิ์)
- ของแต่งจุดเด่นที่ตัดคลิปได้: หลังคาทรงหูแมว ป้ายรูปอุ้งเท้า น้ำพุแมวที่ลานกลาง
- เน้นให้ภาพเล็กบนมือถือยังดูออก ใช้รูปทรงใหญ่ ไม่ใส่รายละเอียดจุกจิก
- ระวังจำนวน Part ให้มือถือเครื่องเล็กยังลื่น ตั้งเป้าไว้ไม่เกินราว 300 ชิ้นต่อร้าน

## 5. การกดและ UI (เล่นง่ายทั้ง PC และมือถือ)

- การกดทั้งเกมใช้ ProximityPrompt แบบเดียวกัน ทั้งสถานีทำเมนูและตู้อัปเกรด เรียนรู้ครั้งเดียวเล่นได้ทั้งเกม
- เมนูอัปเกรดเปิดได้ 2 ทาง: ปุ่มบนจอที่ค้างไว้ตลอด กับตู้อัปเกรดในร้าน
- ไม่ใช้แท่นยืนกดแบบ tycoon คลาสสิก เพราะบนมือถือเดินเหยียบพลาดง่าย และกินพื้นที่ในร้าน
- ปุ่มใหญ่พอให้นิ้วกดถนัด และใช้ขนาดแบบสัดส่วนจอ (Scale) ไม่ล็อกเป็นพิกเซล
- ไม่วางปุ่มทับจอยซ้ายล่างและปุ่มกระโดดขวาล่างของมือถือ ปุ่มอัปเกรดอยู่ขวากลางจอ ตัวเลขเหรียญอยู่บนกลาง
- เมนูอัปเกรดมี 3 แถว (ความเร็ว, ที่นั่ง, ราคา) แต่ละแถวมีปุ่มซื้อปุ่มเดียว

## 8. วิธีเปิดดูใน Studio

**ไฟล์โค้ด** (`src/server/`):
- `Main.server.luau` สร้างแมพตอนเซิร์ฟเวอร์เปิด
- `Map/init.luau` ตำแหน่ง 6 ช่อง + พื้นโลก + กำแพงล่องหน
- `Map/Shop.luau` ร้านต้นแบบ (แก้ที่นี่ ทุกร้านเปลี่ยนตาม)
- `Map/Plaza.luau` ลานกลาง น้ำพุแมว จุดเกิด
- `Map/Palette.luau` สีทั้งหมด
- `Map/Util.luau` ตัวช่วยสร้างชิ้นส่วน

**ขั้นตอน:**
1. เปิด Terminal ในโฟลเดอร์นี้ แล้วรัน `rojo serve`
2. เปิด Roblox Studio สร้างเพลสใหม่ (เทมเพลต Baseplate ก็ได้ สคริปต์จะลบ Baseplate กับ SpawnLocation เดิมให้)
3. แท็บ Plugins → Rojo → Connect
4. กด Play แมพจะถูกสร้างตอนเริ่มเล่น
5. ถ้าอยากเห็นแมพตอนยังไม่กด Play ให้วางใน Command Bar:
   `require(game.ServerScriptService.Server.Map:Clone()).build()`
   (ต้อง `:Clone()` เพราะ Studio จำโมดูลเก่าไว้ ถ้าไม่ clone จะไม่เห็นโค้ดที่แก้ล่าสุด)

**ข้อความในเกมเป็นภาษาอังกฤษ** (Coffee, Upgrade, Claim Shop) ให้ผู้เล่นทั่วโลกอ่านได้ และตรงกับคำค้น "cat cafe"

## 9. แผนขั้นที่ 6: Core loop + สัตว์หลายแบบ + เพื่อน

สถานะ: **6A เสร็จ ทดสอบผ่านครบ** · 6B ยังไม่เริ่ม รอสั่ง (5 พ.ย. 2026)

**กำลังทำ 6B** (เริ่ม 6 พ.ย.) — ข้อ 7 หมา, ข้อ 8 แพนด้า, ข้อ 9 ยูนิคอร์น ผ่านแล้ว · ข้อ 10 ช่วยเสิร์ฟ เขียนแล้วแต่ข้ามการทดสอบไปก่อน · หลัง 6A ทำเพิ่มแล้ว: แมวโฉมใหม่ (ส้ม + ลายสลิด), ถังขยะ, ตัวเลขเหรียญบนจอ, คิวห่าง 6 studs · ค้าง: ID เสียงกระดิ่ง + เสียงยูนิคอร์น (`Config.Sounds.Coin`, `Config.Sounds.Unicorn` ยังว่าง)

เพิ่มเข้ามาในขั้นนี้ตามที่สั่ง (5 พ.ย.): เพื่อนมาเยี่ยม/ช่วยเสิร์ฟ (เดิมอยู่สัปดาห์ 4), หมาใจร้อน, แพนด้าสั่งเยอะ, ยูนิคอร์นหายาก
แบ่งเป็น **6A** core loop กับแมว และ **6B** สัตว์อื่น + เพื่อน

**เป้าหมาย:** ผู้เล่นเล่นครบ 1 รอบได้ภายใน 10–30 วินาที
จองร้าน → ลูกค้าเดินเข้าคิว → กดทำเมนูที่สถานี → รอไม่กี่วินาที → เสิร์ฟ → ได้เหรียญ
แล้วมีเหตุผลให้เล่นต่อ: ลูกค้าแต่ละแบบเล่นไม่เหมือนกัน, ลุ้นยูนิคอร์น, ชวนเพื่อนมาช่วย

### 9.2 ระบบย่อย

**ก. จองร้าน**
- ProximityPrompt "Claim Shop" ที่ `ClaimPad` (PC กด E, มือถือแตะ)
- เซิร์ฟเวอร์เช็กว่าผู้เล่นยังไม่มีร้าน และช่องนั้นว่าง แล้วจึงตั้ง `OwnerUserId` ของช่อง
- ป้ายร้านเปลี่ยนจาก "Free shop" เป็นชื่อผู้เล่น แล้วซ่อนแท่นจอง
- พอผู้เล่นออกจากเกม ช่องกลับเป็นว่าง ลูกค้าในร้านหายหมด

**ข. ลูกค้า (เดิน คิว นั่ง — ใช้กับสัตว์ทุกแบบ)**
- เกิดเฉพาะร้านที่มีเจ้าของ ทุก ~6–10 วินาที ถ้าคิวยังไม่เต็ม 5 ตัว
- เดินตาม `CustomerSpawn` → `WP1` → `WP2` → `WP3` → ช่องคิวว่างช่องท้ายสุด
- ตัวหน้าออกจากคิวเมื่อไหร่ ตัวหลังขยับขึ้นมา
- ตัวที่ถึง `Q1` จะมีป้ายลอยบอกเมนูที่สั่ง สุ่มจากสถานีที่เปิดอยู่ (แพนด้าสั่งหลายอย่าง ดูข้อ จ.)
- เสิร์ฟแล้ว ถ้ามีโต๊ะว่างจะไปนั่งที่ `SitPoint` ราว 5 วินาที แล้วเดินออก ถ้าไม่มีโต๊ะว่างจะเดินออกเลย
- ขาออกเดินเส้นเดิมย้อนกลับ ถึง `CustomerSpawn` แล้วหายไป
- นิสัยของแต่ละสัตว์อยู่ข้อ จ.

**ค. ทำเมนู + เสิร์ฟ**
- ProximityPrompt "Make Coffee" / "Make Bakery" / "Make Milkshake" ที่แต่ละสถานี
- กดแล้วสถานีขึ้นป้าย "Making..." ตามเวลาทำของเมนูนั้น เสร็จแล้วผู้เล่นถือของ 1 ชิ้น (มีชิ้นเล็ก ๆ สีเมนูติดมือ)
- ถือได้ทีละ 1 ชิ้น ระหว่างที่ถืออยู่จะกดทำเมนูใหม่ไม่ได้
- ProximityPrompt "Serve" อยู่ที่ลูกค้าตัวหน้าสุด ถ้าของในมือไม่ตรงกับที่สั่ง ป้ายจะบอกว่า "Wants Coffee" และไม่รับของ
- เสิร์ฟถูกแล้วได้เหรียญตามราคาเมนู มีเสียงกระดิ่งกับตัวเลข "+5" ลอยขึ้น
- Prompt ในร้านใช้ได้เฉพาะเจ้าของร้านกับคนที่กด Yes มาช่วยเสิร์ฟ (ดูข้อ ฉ.) คนอื่นกดแล้วขึ้นว่า "Owner & helpers only"

**ง. เหรียญ + กันโกง**
- เหรียญเก็บในเซิร์ฟเวอร์อย่างเดียว ฝั่งผู้เล่นมีแค่ตัวเลขไว้โชว์
- ฝั่งผู้เล่นส่งคำสั่งเข้าเซิร์ฟเวอร์ได้แค่ 2 อย่าง: "ขอช่วยร้านนี้" (HelpRequest) กับ "ไล่คนช่วยคนนี้" (RemoveHelper) เซิร์ฟเวอร์ตรวจเองทุกอย่าง (ร้านมีจริง มีเจ้าของ ยืนใกล้เคาน์เตอร์จริง ไม่ถูกไล่ไว้ คนช่วยไม่เต็ม ไล่ได้เฉพาะคนในร้านตัวเอง กดถี่ถูกตัด) · ที่เหลือใช้ ProximityPrompt และประกาศยูนิคอร์นเป็น RemoteEvent ทางเดียวจากเซิร์ฟเวอร์
- เซิร์ฟเวอร์เช็กทุกครั้งที่มีการกด: เป็นเจ้าของร้านหรือคนช่วยเสิร์ฟของร้านนี้ไหม ทำเมนูเสร็จจริงไหม (จับเวลาฝั่งเซิร์ฟเวอร์) และของในมือตรงกับที่ลูกค้าสั่งไหม
- ขั้นนี้ยังไม่เซฟ ออกจากเกมแล้วเหรียญหาย จะต่อ DataStore ในสัปดาห์ 2

**จ. สัตว์ 4 แบบ** (ทำเองจากรูปทรงง่าย ๆ แบบรูปปั้นแมวที่ลานกลาง ไม่ใช้โมเดลจาก Creator Store)

| สัตว์ | นิสัย | สั่ง | จ่าย | โอกาสเกิด | จุดเด่นหน้าตา |
| --- | --- | --- | --- | --- | --- |
| แมว | ใจเย็น รอได้ไม่จำกัด | 1 อย่าง | ×1 | 60% | หูแหลม หาง |
| หมา | ใจร้อน มีหลอดเวลาบนหัว | 1 อย่าง | ×1 + ทิปถ้าเสิร์ฟไว | 25% | หูตก ลิ้นแลบ |
| แพนด้า | สั่งเยอะ จ่ายหนัก | 2–3 อย่าง | ×1.5 ทุกชิ้น | 13% | ตัวใหญ่ หูกลมดำ ขอบตาดำ |
| ยูนิคอร์น | หายาก | 1 อย่าง | ×10 | 2% | เขาสีรุ้ง ประกายรอบตัว |

- **หมา:** เริ่มนับเวลาตอนถึง `Q1` (ไม่นับตอนต่อแถว ไม่งั้นหมาที่อยู่ท้ายแถวไม่มีทางทัน) หลอดเวลาเปลี่ยนสีจากเขียวเป็นแดง
  - เสิร์ฟภายใน 8 วินาที ได้ทิปเพิ่ม 50%
  - หมดเวลา 20 วินาที หมาเดินออกโดยไม่จ่าย ไม่หักเหรียญที่มีอยู่ แค่พลาดรายได้รอบนั้น
- **แพนด้า:** ป้ายบนหัวโชว์ทุกอย่างที่สั่ง เสิร์ฟทีละชิ้น ชิ้นที่ได้แล้วขึ้นเครื่องหมายถูก ได้เหรียญทุกครั้งที่เสิร์ฟ 1 ชิ้น ครบแล้วค่อยไปนั่งโต๊ะ
- **ยูนิคอร์น:**
  - ร้านหนึ่งมีได้ทีละตัว และหลังตัวล่าสุดต้องรอ 2 นาทีก่อนจะสุ่มเจออีก
  - มาถึงแล้วมีประกาย เสียงพิเศษ และประกาศให้ทั้งเซิร์ฟเวอร์เห็น "A Unicorn visited ‹ชื่อ›'s café!" (จุดตัดคลิป + โชว์เพื่อน)
  - สุ่มเจอฟรีเท่านั้น **ไม่ขายโอกาสเจอด้วยเงินจริง** ตามหลักจริยธรรมในแผนหลัก

**ฉ. เพื่อน**
- **มาเยี่ยม:** ทุกคนเดินเข้าร้านใครก็ได้อยู่แล้ว เพิ่มปุ่ม **Invite** บนจอ (ขวากลาง ใต้ตำแหน่งปุ่มอัปเกรด) กดแล้วเปิดหน้าต่างชวนเพื่อนของ Roblox ให้เข้ามาเซิร์ฟเวอร์เดียวกัน
- **ช่วยเสิร์ฟ (เปลี่ยน 6 พ.ย.):** ใครก็ได้เดินเข้าโซนเคาน์เตอร์ร้านคนอื่น → หน้าต่างถาม "Help serve at ‹ชื่อ›'s café?" Yes / No → กด Yes แล้วใช้สถานีและเสิร์ฟร้านนั้นได้ ถือของได้ทีละชิ้นเหมือนเจ้าของ · ช่วยได้ทีละร้าน · ร้านหนึ่งมีคนช่วยได้ 3 คน
- **เจ้าของได้แจ้งเตือน** "‹ชื่อ› is helping you serve!" พร้อมปุ่ม **Remove** (หายเองใน 6 วินาที) · กด Remove แล้วคนนั้นหลุด ของในมือหาย และหน้าต่างไม่ถามร้านนี้อีกจนกว่าเจ้าของคืนร้าน
- **เหรียญ:** คนช่วยเสิร์ฟแล้ว เจ้าของได้เหรียญเต็มจำนวน และคนช่วยได้โบนัส 50% (สร้างเพิ่ม ไม่หักจากเจ้าของ) ขึ้น "Helper +X"
- ปุ่ม Invite เป็น UI ชิ้นแรกของเกม ทำตามหลักในหัวข้อ 5 (ปุ่มใหญ่ ขนาดตามสัดส่วนจอ ไม่ทับจอยมือถือ)

### 9.6 วิธีทดสอบ

**6A**
- เล่นคนเดียว: จองร้าน → ลูกค้าตัวแรกมาถึงคิวภายใน ~10 วินาที → ทำเมนู → เสิร์ฟ → เหรียญเพิ่มตามราคา
- เสิร์ฟผิดเมนูต้องไม่ได้เงิน · กดทำเมนูซ้ำตอนถือของอยู่ต้องทำไม่ได้
- คิวเต็ม 5 ตัวแล้วต้องหยุดเกิดลูกค้า · เสิร์ฟแล้วตัวหลังต้องขยับขึ้นมา
- Test → Clients and Servers ตั้ง 2 ผู้เล่น: จองคนละร้าน ห้ามกดใช้ของในร้านคนอื่นได้ · ผู้เล่นออกแล้วร้านต้องว่าง
- Device Emulator ของ Studio เลือกมือถือ: ปุ่ม Prompt แตะง่าย ไม่ทับจอยกับปุ่มกระโดด

**6B**
- หมา: ปล่อยให้หมดเวลา → หมาเดินออก เหรียญไม่ลด · เสิร์ฟภายใน 8 วินาที → ได้ทิป
- แพนด้า: เสิร์ฟทีละชิ้นได้เงินทุกชิ้น ครบแล้วไปนั่ง · เสิร์ฟของที่ไม่อยู่ในรายการต้องไม่รับ
- ยูนิคอร์น: ใน Config มีสวิตช์ทดสอบให้เกิดยูนิคอร์นทันที (ใช้ได้เฉพาะใน Studio) → เห็นประกายและประกาศทุกจอ · ร้านเดียวต้องไม่มี 2 ตัวพร้อมกัน
- ช่วยเสิร์ฟ: เปิด 2 ผู้เล่นใน Studio · Player2 เดินไปเคาน์เตอร์ร้าน Player1 → หน้าต่างโผล่ · กด No → ไม่ช่วย กดในร้านไม่ได้ · กด Yes → Player1 เห็นแจ้งเตือน, Player2 เสิร์ฟได้ + ได้โบนัส · Player1 กด Remove → Player2 กดในร้านไม่ได้อีก และหน้าต่างไม่โผล่ร้านนี้อีก
- ปุ่ม Invite: ใน Studio หน้าต่างชวนเพื่อนอาจไม่เปิด ต้องลองในเกมจริงหลังเผยแพร่

## 10. แผนสัปดาห์ 2: เซฟ + อัปเกรด + เมนูอัปเกรด (วางแผน 7 พ.ย. 2026)

**สถานะ:** เริ่มทำ 7 พ.ย. · ข้อ 1–2 (Config + เซฟ) ผ่าน · ข้อ 3–4 (อัปเกรด + เมนู) + ได้ร้านอัตโนมัติ ทดสอบผ่าน · เซฟระดับอัปเกรดผ่าน

เป้าหมาย: เล่นแล้ว**มีอะไรสะสม** เหรียญไม่หายเมื่อออกเกม เอาเหรียญไปอัปเกรดร้านให้ได้เงินเร็วขึ้น แล้วให้เพื่อน 10–20 คนลองเล่น
(เมนู 3 อย่างในไฟล์ออกแบบเกม ทำแล้วตั้งแต่ขั้น 6)

### 10.1 ขอบเขต

| ทำในสัปดาห์นี้ | ยังไม่ทำ |
| --- | --- |
| เซฟเหรียญ + ระดับอัปเกรด (DataStore) | รายได้ออฟไลน์, Game Pass (สัปดาห์ 3) |
| อัปเกรด 3 อย่าง: ความเร็ว, ที่นั่ง, ราคา | ปลดล็อกเมนูใหม่ Slot4–5 (สัปดาห์ 4) |
| เมนูอัปเกรดบนจอ เปิดจากปุ่มขวากลาง + ตู้อัปเกรดในร้าน | ของแต่งร้าน (สัปดาห์ 3) |
| ให้เพื่อนลองเล่น + จดว่าเล่นซ้ำไหม | ระบบเก็บสถิติละเอียด (หลังเปิดตัว) |

### 10.2 เซฟข้อมูล

- เก็บต่อผู้เล่น (ตาม UserId): `{ version = 1, coins, upgrades = { Speed, Seats, Price } }`
- **ไม่เซฟว่าจองร้านไหน** เข้าเกมครั้งหน้าจองร้านไหนก็ได้ อัปเกรดติดตัวผู้เล่นไปใช้กับร้านที่จองใหม่
- โหลดตอนเข้าเกม · เซฟอัตโนมัติทุก 60 วินาที · เซฟตอนออกเกม · เซฟทุกคนตอนเซิร์ฟเวอร์ปิด
- **โหลดไม่สำเร็จ** (Roblox ล่ม): ลองใหม่ 3 ครั้ง ถ้ายังไม่ได้ ให้เล่นได้แต่**ไม่เซฟทับ** ของเดิมจะได้ไม่หาย แล้วขึ้นข้อความบอกผู้เล่น
- ยังโหลดไม่เสร็จ = จองร้านไม่ได้ (กันเหรียญเริ่มจาก 0 แล้วเซฟทับ)
- ใช้ `UpdateAsync` ไม่ใช่ `SetAsync` และกันการเซฟซ้อนกัน 2 เซิร์ฟเวอร์ (ผู้เล่นย้ายเซิร์ฟเร็ว ๆ)
- Studio กับเกมจริงใช้ที่เก็บข้อมูลคนละชื่อ (ดู 10.7) ทดสอบใน Studio แล้วข้อมูลจริงไม่เพี้ยน
- ใน Studio ต้องเปิด Game Settings → Security → **Enable Studio Access to API Services** ก่อน ถึงจะเซฟได้

### 10.3 อัปเกรด 3 อย่าง (ค่าเริ่มต้น ปรับได้ที่ Config)

| อัปเกรด | ผลต่อระดับ | ระดับสูงสุด | ราคาระดับแรก → ระดับละ |
| --- | --- | --- | --- |
| **ความเร็ว** (Speed) | เวลาทำเมนู −12% | 5 (เหลือ 40%) | 40 → ×1.8 |
| **ที่นั่ง** (Seats) | เปิดโต๊ะเพิ่ม 1 ตัว (2 → 6) + ลูกค้ามาถี่ขึ้น 1 วินาที (8 → 4) | 4 | 60 → ×2 |
| **ราคา** (Price) | ลูกค้าจ่าย +20% ทุกเมนู | 5 (×2) | 75 → ×2 |

- ผลอัปเกรดใช้ของ**เจ้าของร้าน** คนมาช่วยเสิร์ฟทำในร้านนั้นก็ได้ผลแบบเดียวกัน
- ราคาที่อัปเกรดคูณก่อนตัวคูณสัตว์ (หมาทิป, แพนด้า ×1.5, ยูนิคอร์น ×10)
- โต๊ะที่เปิดใหม่ เปลี่ยนจากสีล็อกเป็นสีปกติ และเด้งเล็กน้อยตอนเปิด
- อัปเกรดแล้วมีผลทันที ไม่ต้องออกเกม
- ตัวเลขชุดนี้ตั้งให้ซื้ออย่างแรกได้ใน 1–2 นาทีแรก แล้วค่อย ๆ นานขึ้น · ปรับหลังให้เพื่อนเทสต์

### 10.4 เมนูอัปเกรด (UI แรกเต็มรูปแบบ)

- **ปุ่ม Upgrades** ขวากลาง อยู่เหนือปุ่ม Invite (ที่เว้นไว้แล้ว) สไตล์เดียวกัน: แคปซูลสีพาสเทล วาดไอคอนด้วย Frame ไม่ใช้อีโมจิ
- **ตู้อัปเกรดในร้าน** ขึ้น prompt "Open Upgrades" (ปุ่ม E) เปิดหน้าต่างเดียวกัน
- หน้าต่างกลางจอ การ์ดสีครีมขอบชมพู ปุ่ม X ปิดมุมขวาบน · มี 3 แถว แต่ละแถวมี:
  - รูปไอคอน + ชื่อ (Speed / Seats / Price)
  - จุดบอกระดับ (เต็ม/ว่าง) เช่น ●●○○○
  - ผลก่อน → หลัง เช่น "Coffee 2.0s → 1.8s", "Tables 2 → 3", "Price +20% → +40%"
  - ปุ่มซื้อปุ่มเดียว บอกราคา · เหรียญไม่พอ = ปุ่มสีเทา · ระดับเต็ม = "MAX"
- ซื้อแล้ว: เหรียญลด แถวเด้ง ไอคอนเหรียญบนจอเด้ง
- มือถือ: ขนาดตามสัดส่วนจอ ปุ่มสูงอย่างน้อย 44 px ไม่ทับจอยและปุ่มกระโดด · หน้าต่างเปิดอยู่ยังเดินได้ (ไม่ล็อกตัวละคร)
- คนที่ยังไม่มีร้านกดเปิดได้ ดูได้ ซื้อได้ (อัปเกรดติดตัวผู้เล่น)

### 10.5 ความปลอดภัย

- ผู้เล่นส่งได้แค่ "ขอซื้ออัปเกรดชื่อนี้" (RemoteFunction `BuyUpgrade`) เซิร์ฟเวอร์ตรวจเอง: ชื่ออัปเกรดมีจริง ยังไม่เต็ม เหรียญพอ ข้อมูลโหลดเสร็จแล้ว กดถี่ถูกตัด
- ราคาและผลอัปเกรดคำนวณที่เซิร์ฟเวอร์จาก Config เท่านั้น ฝั่งผู้เล่นแค่โชว์
- ระดับอัปเกรดส่งให้ฝั่งผู้เล่นทาง player attribute (`Upgrade_Speed` ฯลฯ) อ่านอย่างเดียว
- ตู้อัปเกรดเปิดหน้าต่างฝั่งผู้เล่นเอง (ฟัง prompt ในเครื่อง) ไม่ต้องมี remote เพิ่ม

### 10.6 ไฟล์ที่จะเพิ่ม/แก้

src/server/Game/Economy.luau         แก้: เหรียญมาจาก DataService + มี spend()

src/server/Game/CustomerService.luau แก้: ราคา × อัปเกรด, รอบเกิดลูกค้า, โต๊ะที่ใช้ได้

### 10.7 ตัดสินใจแล้ว (7 พ.ย. 2026) — เลือกตามที่แนะนำทั้ง 6 ข้อ

| เรื่อง | ที่เลือก | เหตุผล |
| --- | --- | --- |
| อัปเกรดที่นั่งมีผลอะไร | **เปิดโต๊ะเพิ่ม 1 ตัว + ลูกค้ามาถี่ขึ้น 1 วินาที ต่อระดับ** | เห็นผลชัด ร้านดูคึกคักขึ้น (ตอบเรื่องค้างจาก 9.7 "โต๊ะมีผลอะไร") |
| ตัวเลขอัปเกรด | **ตามตาราง 10.3** | ปรับหลังให้เพื่อนเทสต์ |
| วิธีเซฟ | **DataStoreService ของ Roblox ตรง ๆ** (UpdateAsync + กันเซฟซ้อน) | ข้อมูลน้อย ไม่ต้องลงโมดูลเพิ่ม |
| ข้อมูล Studio กับเกมจริง | **แยกที่เก็บ** Studio ใช้ชื่อลงท้าย `_Dev` | ทดสอบได้โดยไม่ทำข้อมูลผู้เล่นจริงเพี้ยน |
| สวิตช์ทดสอบ | **มี ใช้ได้เฉพาะ Studio:** "เริ่มใหม่จาก 0" และ "เริ่มด้วย 1,000 เหรียญ" | ลองอัปเกรดได้เร็ว ไม่ต้องเสิร์ฟสะสมนาน |
| เพื่อนเทสต์ | **ทำเสร็จทั้งหมดก่อน แล้วเผยแพร่แบบ Private ส่งลิงก์ให้เพื่อน** พร้อมคำถามสั้น ๆ 3 ข้อ | ได้ฟีดแบ็กจากเกมที่ครบ ยังไม่เปิดให้คนทั่วไป |

### 10.8 ลำดับงาน

1. ☑ Config: Upgrades + ชื่อที่เก็บข้อมูล + สวิตช์ทดสอบ (`Debug.ResetData`, `Debug.StartCoins`)
2. ☑ DataService โหลด/เซฟ + Economy ใช้ข้อมูลที่โหลด → **ทดสอบ: Stop/Play แล้วเหรียญยังอยู่** — ผ่าน 7 พ.ย.
3. ☑ UpgradeService + ผลอัปเกรดในสถานี ลูกค้า โต๊ะ — ผ่าน 7 พ.ย.
4. ☑ เมนูอัปเกรด (ปุ่มบนจอ + ตู้ในร้าน) — ผ่าน 7 พ.ย. (`Debug.StartCoins` ตั้งกลับเป็น 0 แล้ว)
5. ◐ ทดสอบใน Studio รวมมือถือ (ดู 10.9) — เริ่ม 8 พ.ย. ผู้ใช้ทดสอบตามเช็กลิสต์
6. ☐ เผยแพร่ให้เพื่อน 10–20 คนลอง + เก็บคำตอบ

### 10.8.1 เปลี่ยนเพิ่ม (7 พ.ย. 2026): ได้ร้านอัตโนมัติ + เกิดหน้าร้าน

ผู้ใช้ขอให้เหมือนเกมแนวฟาร์ม: เข้าเกมแล้วได้ร้านเลย ไม่ต้องเลือก · ตกลงตามที่แนะนำทั้งหมด

- โหลดเซฟเสร็จ → ได้**ร้านว่างเลขน้อยสุด** (Plot1, Plot2, ...) อัตโนมัติ ลูกค้าเริ่มมาทันที
- ตัวละครเกิดที่**หน้าร้านตัวเอง** (จุดล่องหน `OwnerSpawn` ข้างทางเดิน หันเข้าร้าน) ทั้งตอนเข้าเกมและรีสปอว์น
- **เอาแท่น Claim Shop ออก** · ป้ายยังขึ้น "ชื่อ's shop" / "Free shop"
- ออกเกม = ร้านกลับเป็นว่าง คนเข้าใหม่ได้ต่อ
- ตั้ง **Max Players = 6** (Experience Settings → Places) ทุกคนจึงได้ร้านเสมอ · ถ้าไม่มีร้านว่างจริง เกิดลานกลาง + ข้อความ "All shops are taken"
- ช่วงโหลดเซฟ (1–2 วินาที) จะยืนที่ลานกลางก่อน แล้วถูกย้ายไปหน้าร้าน

### 10.9 วิธีทดสอบ

- เซฟ: ได้เหรียญ → Stop → Play → เหรียญเท่าเดิม · ซื้ออัปเกรด → Stop → Play → ระดับยังอยู่
- ซื้อ: เหรียญไม่พอกดไม่ได้ · ซื้อแล้วเหรียญลดตรงราคา · ระดับเต็มขึ้น MAX
- ผล: ความเร็ว = "Making..." สั้นลง · ที่นั่ง = โต๊ะเปิดเพิ่ม ลูกค้ามาถี่ขึ้น · ราคา = เลขเหรียญที่เด้งสูงขึ้น
- ช่วยเสิร์ฟ: คนช่วยในร้านที่อัปเกรดแล้วได้ผลตามเจ้าของ
- มือถือ: เปิดเมนูจากปุ่มและจากตู้ กดซื้อได้ ไม่ทับจอย
- 2 ผู้เล่น: แต่ละคนเห็นระดับของตัวเอง ไม่ปนกัน
