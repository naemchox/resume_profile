# เลื่อนแล้วกระตุก: velvet-leaf กับ the-terrace — วัดเสร็จแล้ว ยังไม่แก้

**สถานะ: พักไว้ (24 ส.ค. 2026) — jek บอกว่า "ดีไซน์ตอนนี้ก็ดีอยู่แล้ว เก็บคำแนะนำไว้ก่อน"**
ทั้งสองใบ **ไม่ได้ถูกแก้เลยสักบรรทัด** ไฟล์ยังเป็นตัวเดิมทุกตัวอักษร

## เจอมาได้ยังไง
ตอน deploy งาน the-bed ผมเปิดเซิร์ฟเวอร์ :8099 ค้างไว้ ทำให้ `playbook/audit-scroll.mjs`
ได้รันจริงเป็นครั้งแรก (ปกติมันขึ้น "! ข้าม audit-scroll (ไม่มีเซิร์ฟเวอร์)" แล้วผ่านไป)
→ **ด่านนี้ไม่เคยตรวจอะไรเลยมานาน** ของสองใบนี้อยู่บนเว็บจริงแบบ 30fps มาตลอด

## ระเบียบการวัดที่ต้องใช้ (สำคัญกว่าตัวเลข)
วัดรอบเดียวเชื่อไม่ได้ — ระหว่างทางเกือบพลาดสองครั้ง:
1. `glow-clinic-multi` วัดครั้งแรกได้ 31fps → วัดเดี่ยวตอนเครื่องว่าง **60fps ไม่ต้องแก้เลย**
2. สูตร `will-change: opacity` ของ the-terrace วัดรอบเดียวได้ 60fps ผมเกือบบอกว่า "แก้ได้แล้ว"
   → วัดซ้ำ 3 รอบได้ **30fps ทั้งสามรอบ ไม่ช่วยอะไรเลย**

**กติกา: ทุกสูตรต้องวัดซ้ำอย่างน้อย 3 รอบ สลับกับ baseline และห้ามมีแท็บเบราว์เซอร์
หรือ playwright ตัวอื่นเปิดค้างระหว่างวัด** (แท็บ Chrome ของผมเองเคยทำ baseline
เด้งจาก 30 เป็น 60 ทั้งที่โค้ดไม่เปลี่ยน)

## ผลวัดสุดท้าย (3 รอบต่อสูตร เครื่องว่าง)

### velvet-leaf — ตัวกิน: `.neon-glow` แอนิเมต `filter: drop-shadow`
```
30 · 30 · 30 fps   baseline                  เฟรมยาว 255/235/247
60 · 60 · 60 fps   B  เงานิ่งอย่างเดียว        เฟรมยาว  62/131/ 58
60 · 60 · 60 fps   B2 เงานิ่ง + ปิด mix-blend  เฟรมยาว  15/ 14/  4   ← สะอาดสุด
```
ต้นเหตุ:
```css
.neon-glow{animation:neon-breathe 7s ease-in-out 2.7s infinite}
@keyframes neon-breathe{
  0%,to{filter:drop-shadow(0 0 12px …) drop-shadow(0 0 46px …)}
  50%  {filter:drop-shadow(0 0 20px …) drop-shadow(0 0 70px …)}}
```
`filter` คอมโพสิเตอร์ทำไม่ได้ ต้องคำนวณเงาฟุ้งเกาส์เซียนสองชั้น (รัศมีนอก 46-70px)
ใหม่ทุกเฟรม บนกล่อง 102k px² **และวิ่งตลอดเวลา ไม่ใช่เฉพาะตอนเลื่อน**

ยาที่เสนอ (B2) = ให้ไฟติดค้างที่ความสว่างกลาง ไม่หายใจ:
```css
.neon-glow{animation:none;filter:drop-shadow(0 0 16px rgba(239,199,94,.62))
                                 drop-shadow(0 0 58px rgba(124,58,237,.52))}
.mix-blend-overlay,.mix-blend-screen{mix-blend-mode:normal}
```
**ข้อแลก: เสีย "ไฟหายใจ" (ป้ายนีออนเรืองขึ้น-จางลง รอบละ 7 วิ)** — นี่คือเหตุผลที่ jek พัก
ถ้าจะเก็บลูกเล่นไว้ ต้องแยกเงาไปอยู่เลเยอร์ของตัวเองแล้วครอสเฟด `opacity` แทน (ยังไม่ได้ลอง)

### the-terrace — ตัวกิน: `.hero-glow` (ไม่ใช่ `.band::after`)
```
30 · 60 · 57 fps   baseline                      ← baseline เองแกว่ง
30 · 30 · 30 fps   C  will-change:opacity ทั้งคู่  ← ไม่ช่วยเลย (สูตรที่ผมเดาผิด)
30 · 30 · 58 fps   G1 ปิดไฟที่ .band::after       ← ไม่ใช่ตัวนี้
60 · 60 · 60 fps   G2 ปิดไฟที่ .hero-glow         เฟรมยาว 4/0/2  ← ตัวนี้ตัวเดียว
```
`.hero-glow` = `position:absolute; inset:0` คลุมฮีโร่ทั้งบล็อก (978k px²) แอนิเมต
`tt-warm` (opacity .55↔1 รอบละ 11 วิ) **opacity ควรจะฟรี แต่แผ่นนี้ไม่ได้ขึ้นเลเยอร์ของตัวเอง**
เบราว์เซอร์เลยวาดทุกอย่างใต้มันใหม่ทุกเฟรม รวมรูปฮีโร่ 1,524k px²
(ยืนยันด้วย: ซ่อนรูปทั้งหน้า → 60fps ทันที)

ยังไม่มียาที่พิสูจน์แล้ว — `will-change` เฉยๆ ไม่พอ ครั้งหน้าให้ลอง:
`transform:translateZ(0)` + `contain:paint` บน `.hero-glow`, หรือย้ายไฟไปเป็น
เลเยอร์ลูกที่ไม่มีอะไรอยู่ใต้, หรือหยุดไฟเมื่อฮีโร่เลื่อนพ้นจอ
**ห้ามใส่ `will-change:opacity` แล้วเคลมว่าแก้แล้ว — วัด 3 รอบได้ 30fps ทั้งสามรอบ**

## รูที่ควรอุดต่างหาก (ไม่เกี่ยวกับดีไซน์ ทำได้เลย)
`audit-scroll` / `audit-multi` / `audit-mobile` ทั้งสามตัวจะ **"ข้าม" เงียบๆ** ถ้าไม่มี
เซิร์ฟเวอร์ที่ :8099 แล้ว deploy ก็ผ่าน = SKIP กลายเป็น PASS โดยไม่มีใครรู้
ควรให้ `deploy.mjs` เปิดเซิร์ฟเวอร์เองก่อนถึงด่านพวกนี้ แทนที่จะรอให้คนเปิดไว้ให้
