# PROMPT-MOBILE.md — พรอมป์ "ปรับสัดส่วนหน้าจอมือถือ" (สูตรจาก tarmsung 2026-08-20)

> ที่มา: jek ส่งภาพการ์ด "ปรึกษาฟรี" ของ tarmsung มาแล้วพิมพ์สั้นๆ ว่า
> *"ปรับสัดส่วนของส่วนนี้ใน Mobile View"* — วัดแล้วการ์ดใบเดียวสูง **525px บนจอ 390**
> คือ **สองในสามของจอ** เพื่อพูดเรื่องเดียว. แก้เสร็จเหลือ 431px โดยไม่ตัดเนื้อหาออกสักตัว
>
> ใช้คู่กับ `PROMPT-JUED.md` — จืดคือ "เร่งไฟให้ของที่มี", อันนี้คือ "จัดของที่มีให้พอดีจอเล็ก"
> ลำดับที่ใช้จริง: **จืดก่อน → มือถือทีหลัง** (เพราะ pass จืดมักเพิ่มของที่กินพื้นที่)

## แก่นของสูตร (4 ชั้น)

1. **วัดก่อน ห้ามเดา** — เปิดที่ 390 จริง แล้วอ่านความสูงเป็น px ของ "การ์ด / บล็อกย่อย / ตัวหนังสือ"
   ออกมาเป็นตัวเลข. ปัญหาสัดส่วนคือปัญหาที่พูดเป็นตัวเลขได้ ถ้ายังพูดไม่ได้แปลว่ายังไม่รู้ว่าอะไรพัง
2. **หา "รูปทรงของจอคอม" ที่หลงเหลืออยู่** — เกือบทุกครั้งอาการไม่ได้มาจากของเยอะ แต่มาจากบล็อกที่ยัง
   ใช้ layout/ไซซ์ของจอกว้างอยู่บนจอ 390 (คอลัมน์ที่ควรเป็นแถว, หัวข้อไซซ์เดสก์ท็อป, ชิปที่ล้น 3 แถว)
3. **เรียงใหม่ ไม่ตัดเนื้อหา** — ห้ามซ่อน/ลบข้อความเพื่อให้สั้นลง. ที่ยอมให้ตัดได้มีอย่างเดียวคือ
   *ของประดับ* ที่ไม่มีข้อมูล (เช่น อุปกรณ์ตัวที่เล็กจนอ่านไม่ออกในคลัสเตอร์ mockup)
4. **พิสูจน์ด้วยตัวเลข + ภาพ** — รายงาน ก่อน→หลัง เป็น px, และดูภาพจริงทั้ง **390 / 360 / ธีมมืด**
   ก่อนบอกว่าเสร็จ

## ตารางอาการ → ท่าแก้ (เจอซ้ำจริงทุกงาน)

| อาการบนจอ 390 | ต้นเหตุ | ท่าแก้ |
|---|---|---|
| ป้าย/ราคา/ปุ่ม เรียงตั้ง 3 ชั้น มีอากาศคั่นเยอะ | คอลัมน์ขวาของ layout จอกว้างถูก stack ตรงๆ | ทำเป็น **แถวราคา**: ป้ายซ้าย · ตัวเลข/คำขวา เรียง baseline เดียวกัน แล้วปุ่ม+หมายเหตุค่อยกินเต็มความกว้าง (ประหยัด ~60px) |
| หัวข้อกินสองบรรทัดครึ่ง | `--text-2xl`/`3xl` เป็น clamp ที่ยังใหญ่ที่ 390 | ลดเป็น `--text-xl` เฉพาะใน media query + `line-height: snug` |
| ชิป 5 อันล้น 3 แถว | ไซซ์ชิปเท่าจอคอม | `--text-xs` + บีบ padding แนวนอน → เหลือ 2 แถว (ไม่ลดจำนวนชิป) |
| ป้ายกำกับลอยห่างรูปมาก บนจอกว้าง | grid ยืดเต็ม container ป้ายเลยไปติดขอบจอ | cap ความกว้างบอร์ด (`max-width` + `margin-inline:auto`) ให้ = กว้างรูป + สองคอลัมน์ตัวอักษร |
| รูป/คลัสเตอร์ mockup ใหญ่เกินครึ่งจอแต่ "อ่านไม่ออก" | ของหลายชิ้นย่อพร้อมกันจนทุกชิ้นเล็ก | เหลือ 2 ชิ้นที่ใหญ่พอจะอ่าน (เช่น จอใหญ่ + มือถือ) ซ่อนที่เหลือใน media query |
| ช่องว่างบน-ล่างเยอะจนต้องเลื่อนหาเนื้อ | section padding/gap เป็นค่าจอกว้าง | ลด `gap`/`padding` ลงหนึ่งขั้นในสเกล ไม่ใช่ตั้งเลขลอย |
| ปุ่มเล็กลงตามไปด้วย | ไปลดไซซ์ทั้งบล็อกรวมปุ่ม | **ห้ามแตะปุ่ม** — พื้นที่แตะต้อง ≥ 44px เสมอ |

## พรอมป์ (ก๊อปทั้งบล็อก แล้วแก้ `[[ ]]`)

```
งาน: ปรับ "สัดส่วน" ของ [[ชื่อ section/การ์ด]] ใน [[ไฟล์เว็บ]] เฉพาะบนจอมือถือ
ห้ามแตะหน้าตาบนจอกว้าง — ทุกอย่างที่แก้ต้องอยู่ใน media query เท่านั้น

ขั้นที่ 1 — วัดก่อน (ห้ามเสนอวิธีแก้ก่อนมีตัวเลข)
เปิดหน้าที่ความกว้าง 390 จริง แล้วรายงานเป็นตาราง: ความสูงเป็น px ของการ์ดทั้งใบ
และของบล็อกย่อยทุกอัน + font-size ที่คำนวณจริงของหัวข้อ/ตัวเลขเด่น
บอกด้วยว่าการ์ดกินกี่ % ของความสูงจอ

ขั้นที่ 2 — ชี้ต้นเหตุ
บอกว่าแต่ละบล็อก "ยังใช้รูปทรงของจอคอม" ตรงไหน (คอลัมน์ที่ควรเป็นแถว, ไซซ์ตัวอักษร
ที่ไม่ได้ลด, ของที่ล้นแถว, gap/padding ค่าจอกว้าง) — เรียงจากอันที่กินพื้นที่มากสุดก่อน

ขั้นที่ 3 — แก้
- ห้ามซ่อนหรือลบข้อความ/ชิป/ฟีเจอร์ใดๆ เพื่อให้สั้นลง ยกเว้นของประดับที่ไม่มีข้อมูล
  (ถ้าจะตัดของประดับ ให้บอกเหตุผลกำกับ)
- ห้ามลดขนาดปุ่ม/พื้นที่แตะ ต้อง >= 44px
- ใช้ token ที่มีอยู่ (--text-*, --space-*) ห้ามตั้งเลขลอยใหม่
- แก้ในไฟล์ CSS หลักใต้ media query เดิมของบล็อกนั้น ถ้ายังไม่มีให้สร้างที่เดียว ไม่กระจาย
- เขียนคอมเมนต์กำกับว่า "ก่อนแก้สูงเท่าไหร่ / แก้อะไร / เพราะอะไร" (ตัวเลขจริง)

ขั้นที่ 4 — พิสูจน์
วัดซ้ำที่ 390 รายงาน ก่อน→หลัง เป็น px, แล้วแนบภาพจริง 390 / 360 / ธีมมืด
และรัน `node playbook/verify.mjs <โฟลเดอร์>` ต้องขึ้น "ตก 0"

ส่งงาน: ตาราง ก่อน/หลัง + ลิสต์ว่าแก้อะไรไปกี่จุด + ยืนยันว่าไม่มีเนื้อหาไหนหายไป
```

## กติกาที่ห้ามแลกกับความสั้นของหน้า

- **ไม่ตัดเนื้อหาเพื่อความสวย** — การ์ดที่สั้นลงเพราะลบข้อความ ไม่ใช่การแก้สัดส่วน แต่คือการแก้โจทย์อื่น
- **พื้นที่แตะ ≥ 44px** และปุ่มหลักยังต้องเต็มความกว้างเหมือนเดิม
- **แตะเฉพาะใน media query** — จอกว้างต้องเหมือนเดิมทุก px (เทียบภาพก่อน/หลังที่ 1440 ด้วยถ้าไม่มั่นใจ)
- **ธีมมืดต้องดูด้วยตาจริง** ทุกครั้ง — งานนี้ jek ส่งภาพมาเป็นธีมมืดเสมอ
- **เทส 360 ไม่ใช่แค่ 390** — ชิปกับหัวข้อไทยจะขึ้นแถวใหม่ตรง 360 บ่อยมาก
- เจอ pattern ใหม่ → **เขียนเพิ่มลงตารางอาการข้างบน** ไม่งั้นงานหน้าเจอซ้ำ
