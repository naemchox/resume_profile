## ด่าน 2 — เครื่องตรวจ (บังคับ)

```bash
node playbook/verify.mjs /path/to/project     # ต้องขึ้น "ตก 0"
node playbook/audit-sameness.mjs             # ต้องไม่มีคู่ไหน "ตก"
node playbook/audit-mobile.mjs               # ต้องไม่มี "กล่องยุบจนเฉือนเนื้อหา"
node playbook/audit-height.mjs               # DEMO-SPEC S1.3 — ก้อนหนักผิดตำแหน่ง/หน้าสูงผิดปกติ
node playbook/audit-motion.mjs               # DEMO-SPEC S2 — สองตัวขับ · อนิเมต filter · รูปไม่บอกขนาด
node playbook/check-demo-rules.mjs --all     # DEMO-SPEC S1.4 + S2.10-12
node playbook/audit-nav.mjs                  # หัวเว็บทุกใบต้องใช้กลไกเดียวกัน (ไม่ใช่แค่ "หดได้")
node playbook/audit-pages.mjs --inv <INVENTORY.md> --demo <โฟลเดอร์>   # S1.0 reference + S1.1 หน้าครบ
node playbook/audit-assets.mjs --ref <โฟลเดอร์ลูกค้า> --demo <index.html> --inv <INVENTORY.md>  # S1.1 รูปครบ
```

⚠️ อ่านบรรทัด ⚠️ ในผลตรวจด้วย — `audit-height` กับ `audit-motion` จะฟ้องว่า "วัดไม่ได้"
เมื่อเปิดหน้าไม่ขึ้นหรืออ่านสไตล์ชีตไม่ได้ **นั่นไม่ใช่ผ่าน** ต้องตามให้วัดได้ก่อน
(velvet-leaf เคยขึ้นเขียวติดกันหลายรอบทั้งที่ด่านไม่เคยเห็นหน้านั้นเลย — มันเป็น SPA + ประตูยืนยันอายุ)

`audit-mobile.mjs` เปิดทุกหน้าที่ **สองความกว้าง** (390 มือถือจริง · 820 หน้าต่างที่ย่อบนคอม)
มีอยู่ตั้งแต่แรกแต่ไม่เคยถูกต่อเข้าสาย `deploy.mjs` จนวันที่ 23/8/26 — วันที่รีลการ์ดผลงาน
บนจอ ≤1024px เหลือสูง 39px จากที่การ์ดสูง 200px แล้วด่านทุกตัวขึ้นเขียว เพราะทุกตัวมองที่
1440px หมด ตอนนี้มันบล็อกการปล่อยเฉพาะหมวด "กล่องยุบจนเฉือนเนื้อหา" (โชว์ได้ไม่ถึง 60%
ของที่เนื้อในต้องใช้) ส่วนปุ่มเล็ก/ตัวหนังสือเล็ก/ของล้นที่ถูกครอบไว้ = รายงานให้อ่าน ไม่บล็อก

ตรวจให้อัตโนมัติ: rootMargin ของ reveal, unobserve, first-paint fallback, html.js gate,
reduced-motion เคลียร์ start state ครบทุกตัว, grain texture, คอนเทนเนอร์ซ้อนคลาสแคบ,
ของที่หน้าตาเป็นปุ่มแต่กดไม่ได้, หน้าไม่มี CTA เลย, alt/width/height ของรูป,
ไฟล์รูปกำพร้า/หนักเกิน, ฟอนต์ display ที่ไม่มีตัวไทย, header ไม่ sticky,
:focus-visible, aria-labelledby, skip link, contrast script, และ **build ครบตาม BRIEF ไหม**

`audit-sameness.mjs` ตรวจคนละเรื่อง: มันเทียบงานเรา**ข้ามโปรเจกต์** ว่า "ข้างใน" ของสองหน้า
เป็นชุดเดียวกันหรือยัง (หักโครงร่วมของ engine และสูตรฮีโร่ออกแล้ว — ฮีโร่ซ้ำได้) เกิน 50% = ตก
verify.mjs ตรวจ "หน้านี้ทำถูกไหม" ทีละหน้า จึงมองไม่เห็นปัญหาชนิดนี้ตลอดกาล

## ด่าน 3 — ตาคน (เครื่องตรวจแทนไม่ได้)

ถ่ายจริงก่อนตอบ:
```bash
C="/Applications/Google Chrome.app/Contents/MacOS/Google Chrome"
"$C" --headless=new --disable-gpu --hide-scrollbars --virtual-time-budget=9000 \
     --window-size=1440,900 --screenshot=/tmp/a.png "URL?reduce=1"
```
- [ ] **จอ 1440×900: ปุ่มหลักอยู่เหนือ fold ไหม** (พลาดมาแล้ว — รูปสูงเกินดัน CTA ตกจอ)
- [ ] **จอ 390**: อย่าเชื่อ `--window-size=390` ของ headless เครื่องนี้ (ย่อต่ำกว่า ~440px ไม่ได้ แต่ยังครอปภาพให้ = ภาพหลอกว่าล้น) ให้โหลดใน iframe กว้าง 390 แล้วเทียบ `scrollWidth` กับ `clientWidth`
- [ ] เปิดทีละ state จริง (`?flavour=`, `?theme=`) ไม่ใช่เดาว่าตัวแปรทำงาน
- [ ] จ้องภาพแล้วถามว่า **"อันนี้เป็นของแบรนด์นี้ หรือเป็นเทมเพลตที่แปะโลโก้"**

## ด่าน 3.5 — รอบขัด (สองพรอมป์ เรียงตามนี้เสมอ)

ทั้งสองอันเป็นไฟล์พรอมป์ก๊อปวางได้ อยู่ในโฟลเดอร์นี้ (ตัวที่ 0 คือ `PROMPT-BLOCKS.md` ที่ด่าน 0):

1. **`PROMPT-JUED.md` — แก้เว็บจืด** เร่งไฟให้ของที่มีอยู่แล้ว (audit ของตกแต่งที่จางจนไม่เคยขึ้นจอ,
   มาร์กแบรนด์ใช้ใหญ่, motion ที่เป็นของธุรกิจนั้นจริงๆ, ตัวเลขที่วิ่งมา)
2. **`PROMPT-MOBILE.md` — ปรับสัดส่วนมือถือ** วัดเป็น px ที่ 390 แล้วรื้อบล็อกที่ยังใช้รูปทรงจอคอม
   โดยไม่ตัดเนื้อหา

**ลำดับสำคัญ: จืดก่อน มือถือทีหลัง** — pass จืดมักเพิ่มของที่กินพื้นที่ (มาร์กใหญ่, ตัวเลขวิ่ง,
เส้นวาด) ถ้าจัดมือถือก่อนจะต้องจัดใหม่อีกรอบอยู่ดี

- [ ] **รันด่านความสูงกับด่านแอนิเมชันซ้ำ หลังจบรอบขัดทั้งสองอัน** (เพิ่ม 24/8/26)
      ```bash
      node playbook/audit-height.mjs <path>   # จืดเพิ่มของที่กินความสูง อาจดันทะลุเพดาน S1.3
      node playbook/audit-motion.mjs <path>   # จืดเพิ่ม motion อาจใส่ของที่ผิด S2 เข้ามาใหม่
      ```
      สองด่านนี้อยู่ที่ด่าน 2 คือ**ก่อน**รอบขัด ถ้าไม่รันซ้ำ ของที่รอบขัดใส่เข้ามาจะไม่เคยถูกตรวจเลย
      — รูเดียวกับที่ทำให้เดโมผ่านทุกด่านแล้วยังออกมา "สูงเกินไป"
