## 1. สถาปัตยกรรม token (3 ชั้น)

**Tier 1 primitive** — ค่าดิบ ไล่สเกล `--<ชื่อสี>-25 … -950` เขียนเป็น **OKLCH** (perceptually uniform + ครอบ P3)
**Tier 2 semantic** — `--color-bg`, `--color-text`, `--color-accent`, `--color-success` … **ชื่อห้ามผูกกับสี** (`--color-accent` ไม่ใช่ `--color-orange`) เปลี่ยน palette ทั้งเว็บต้องแตะแค่ tier 1
**Tier 3 component** — เฉพาะที่ component นั้นต้องการจริงๆ

กฎที่ใช้ได้ทุกแบรนด์:
- **grayscale-first** — ลำดับความสำคัญมาจากน้ำหนัก+ขนาด+ระยะ สีเป็นชั้นบนสุด ปิดสีทิ้งแล้วหน้าต้องยังอ่านลำดับออก
- **accent สีเดียว** สีที่ 2 ล็อกขอบเขตไว้แคบ (success/tick/live-dot) เขียนกำกับไว้ว่า "ห้ามขยาย"
- neutral ramp ต้อง**เอียงไปทางอุณหภูมิเดียวกับ accent** (accent อุ่น → เทาอุ่น) เทากลางเป๊ะจะดูเป็นจอ ไม่ใช่วัสดุ
- ทุก surface มี **grain texture** ละเอียด (tile ~160px) ให้รู้สึกเป็นวัสดุ
- dark theme ไม่ใช่การกลับสี — เขียน semantic mapping แยกอีกชุดใต้ `[data-theme="dark"]`

## 1b. DESIGN BAR — เกณฑ์ที่ทำให้หน้าดู "ถูกออกแบบ" ไม่ใช่ "ถูกประกอบ"

ส่วนที่เหลือของไฟล์นี้คือ**กลไก** (สี จังหวะ a11y) ซึ่งทำถูกครบแล้วก็ยังได้เทมเพลตสวยๆ อยู่ดี
สิบข้อนี้คือส่วนที่ตัดสินว่ามันดูเป็นงานออกแบบจริงไหม — ตรวจด้วยตา เครื่องตรวจแทนไม่ได้

1. **Reference pass ก่อนเสมอ** — เปิดเว็บที่ดีที่สุด 3 เจ้าในหมวดนั้น เขียน "3 อย่างที่จะขโมย · 3 อย่างที่จะไม่ทำ" ลง BRIEF ก่อนเขียนโค้ดบรรทัดแรก **ข้ามข้อนี้เมื่อไหร่ สมองจะหยิบโครงของงานที่แล้วมาใช้อัตโนมัติ** (เคยเกิดแล้ว: ลูกค้ารายที่สองได้เว็บโครงเดียวกับรายแรกทั้งใบ)
   **21/8/26 เกิดซ้ำอีก 3 หน้า ทั้งที่ข้อนี้เขียนอยู่ตรงนี้แล้ว** — ครัวบ้านสวน/โกลว์ คลินิก/เดอะ เทอเรส
   เป็นหน้าเดียวกันตั้งแต่ฮีโร่ยันฟุตเตอร์ **แต่ข้อสรุปหลังคุยกับ jek คือ "ฮีโร่ซ้ำได้"** —
   สูตรรูปเต็มจอ + หัวเรื่อง + ปุ่มคู่ เป็นของที่ทำงานได้และไม่มีลูกค้าคนไหนเอาหน้าแรกของ
   สองเจ้ามาวางเทียบกัน สิ่งที่ห้ามซ้ำคือ **ข้างใน** (ดูข้อ 4b) วัดแล้วครัวบ้านสวน ↔ โกลว์ คลินิก
   ใช้คำศัพท์ของเนื้อหาใต้ฮีโร่ร่วมกัน 78% = คนที่เลื่อนลงไปเจอหน้าเดิมสองรอบ
   บทเรียนที่เหลือยังเหมือนเดิม: **กฎที่ไม่มีเครื่องจับ = กฎที่ถูกข้ามเงียบๆ**
   → `node playbook/audit-sameness.mjs` (ตัดฮีโร่ออกก่อนวัดแล้ว) รันก่อนบอกว่าเสร็จทุกครั้ง

2. **หนึ่งจอ หนึ่งพระเอก** — ในหนึ่งหน้าจอต้องมีของที่เด่นที่สุดชิ้นเดียว ถ้าชี้ไม่ได้ว่าอันไหน แปลว่ายังไม่มี
3. **ฟอนต์ 2 ตัวพอ** — display 1 + body 1 (เพิ่ม mono ได้เฉพาะเมื่อมี "ตัวเลขที่วัดมาได้" จริงๆ) พาดหัวขนาดใหญ่ `line-height ≤ 1.05` เนื้อความกว้าง 45–75ch
4b. **ข้างในห้ามซ้ำข้ามโปรเจกต์ (ฮีโร่ซ้ำได้)** — ข้อ 4 ห้ามซ้ำ "ในหน้าเดียว" ซึ่งไม่พอ
   เพราะสองงานที่ผ่านข้อ 4 ทั้งคู่ก็ยังใช้ชุดเครื่องมือเดียวกันทั้งชุดได้ (section-head+kicker →
   การ์ด 3 ใบ → steps → facts → แถบตัวเลข) เกณฑ์คือ **ข้อมูลคนละชนิดต้องใช้เครื่องมือคนละอย่าง**
   ลิสต์ราคา ≠ การ์ด · ลำดับเวลา ≠ กริด · การเปรียบเทียบ = ตาราง · ที่ตั้ง = แผนผังที่วาดเอง ·
   ความจุ/วันว่าง = ปฏิทิน — แล้วให้แต่ละงานมี **ลายเซ็นรายละเอียดหนึ่งอย่างที่วิ่งทั้งหน้า**
   (ตัวอย่างที่ดีที่สุดในรีโปนี้คือ velvet-leaf: ใบไม้เส้นทองเป็นทั้ง bullet, ตัวคั่นใต้หัวข้อ,
   favicon และ watermark หลังรูป + วง % หน้าชื่อสินค้า + ตัวอักษรโครงร่างยักษ์เป็นภาพพื้นหลัง)
   และถามด้วยว่า **คนเข้ามาแล้ว "ทำ" อะไรได้บ้าง** ไม่ใช่แค่ "อ่าน" อะไร — หน้าที่กรอง/เลือก/
   เก็บลิสต์ได้ อ่านเป็นคนละผลิตภัณฑ์กับหน้าที่เลื่อนดูอย่างเดียว ต่อให้ฮีโร่เหมือนกันเป๊ะ

4. **รูปทรงของ block ห้ามซ้ำเกิน 2 ครั้งในหน้าเดียว** — ถ้าทุก section เป็น "การ์ด 3 ใบต่อแถว" แปลว่าไม่ได้ออกแบบ แค่เทข้อมูลลงตาราง เลือกรูปแบบตามชนิดข้อมูล (รายการ/เปรียบเทียบ/ลำดับเวลา/ก่อน-หลัง/หลักฐาน/ของที่ต้องเห็นจริง)
5. **กฎ fold** — ปุ่มหลักต้องเห็นได้ทั้งที่ 1440×900 และ 390×844 โดยไม่ต้องเลื่อน (เคยพลาด: รูปสัดส่วน 2:3 กลางหน้าไปดัน CTA ตกจอ)
6. **รูปเลือกจาก "ฉากหลังเข้ากับพื้นเว็บ" ก่อนความสวย** — หน้าพื้นดำต้องใช้รูปฉากหลังมืด + `mask-image` ให้ขอบจางหายไปในพื้น และครอบสัดส่วนตั้งแต่ตอนเตรียมไฟล์ ไม่ใช่ครอบด้วย CSS · รูปถ่ายมือสมัครเล่นแย่กว่าการวาดด้วย CSS เสมอ
7. **ทุกคำต้องเป็นของจริง หรือมีป้ายว่ายังไม่จริง** — ห้ามแต่งราคา/เคสลูกค้า/ตัวเลขขึ้นเอง แล้วปล่อยผ่านเงียบๆ ห้ามคำกลวง ("ครบวงจร" "โซลูชัน" "พรีเมียม")
8. **อะไรที่หน้าตากดได้ ต้องกดได้** — ชิปทรง pill ที่เป็น `<li>` เปล่าคือการหลอกตา และหน้าที่ไม่มีปุ่มพาไปไหนเลยคือหน้าที่ไม่มีจุดเปลี่ยน
9. **จังหวะระยะห่างมาจากสเกลเดียว** — section padding ทุกอันหยิบจาก `--space-*` ห้ามมี margin ตั้งเอง ความไม่สม่ำเสมอของระยะคือสิ่งที่คนดูไม่รู้ว่าคืออะไร แต่รู้สึกว่า "ดูไม่โปร"
10. **ทุก section ต้องตอบคำถามข้อใดข้อหนึ่งใน B3.1 ของ BRIEF ได้** ถ้าตอบไม่ได้ให้ตัดทิ้ง ไม่ใช่เก็บไว้เผื่อ

## 2. Motion doctrine (จุดที่เว็บแพ้ชนะจริง)

**primitive แค่ 5 ท่า duration เดียว** ห้ามคิดท่าเฉพาะกิจรายชิ้น:

```
.reveal          ขึ้น 20px (ค่าเริ่มต้น)
.reveal--left / --right    เลื่อนข้าง 20px
.reveal--scale             0.97 → 1
.reveal--fade              opacity ล้วน (ต้องใช้ curve คนละตัว ดูข้างล่าง)
.reveal--band              แถบเต็มจอ ไม่ขยับ ยาว 1400ms
```

- **1100ms + `cubic-bezier(0.33, 0, 0.3, 1)`** ทุกท่า
- `--fade` ต้องใช้ `cubic-bezier(0.37, 0, 0.63, 1)` — expo-out ใช้ระยะทางหมดใน 1/5 แรก ซึ่งดีกับของที่**เดินทาง** แต่ทำให้ opacity ล้วนดูวูบ
- stagger แค่ 3 ระดับ `.d1/.d2/.d3` = 90/180/270ms

**IntersectionObserver:**
```js
{ threshold: 0.12, rootMargin: "0px 0px 25% 0px" }
```
rootMargin **บวก** = เริ่มตั้งแต่ block ยังอยู่ใต้ fold หนึ่งในสี่จอ animation จบก่อนตาไปถึง
(margin ลบ = ไปถึงตอนยังโปร่งครึ่งเดียว = อาการที่คนเรียกว่า "ไม่ smooth")

- reveal แล้ว `unobserve` ทันที ห้ามย้อนกลับ
- ชิ้นที่อยู่ในจอตั้งแต่โหลด → ใส่ `.in` ทันทีจากการวัด `getBoundingClientRect()` **ไม่ใช่รอ observer** (observer ไม่ยิงใน tab ที่ซ่อน / prerender / session ที่ restore มา)
- start state ทั้งหมด gate ใต้ `html.js` → JS ไม่รัน = หน้ายังอ่านได้ปกติ

**ของใหญ่ห้าม fade** — อะไรที่กว้างเต็ม viewport (คำปิดท้ายตัวใหญ่, แถบเต็มจอ) ใช้ transform/wipe แทน opacity: fade แผ่นใหญ่ = recomposite ทั้งแผ่นทับ texture ทุกเฟรม + มักไปรันตอนหน้ายังเลื่อนอยู่ = กระตุก
ท่าที่ใช้แทน: กล่อง `overflow:hidden` + ดัน `<span>` ข้างในลงไปซ่อนใต้ขอบ แล้วให้เลื่อนขึ้นมา (transform ล้วน raster ครั้งเดียว)

**`prefers-reduced-motion: reduce` ต้องเคลียร์ทุก start state** ไม่ใช่แค่ลด duration — ชิ้นที่ค้างที่ `clip-path: inset(0 0 100% 0)` หรือ `translateY(100%)` จะไม่มีวันโผล่

## 3. Theme toggle

สลับ light/dark ด้วย **wipe เป็นวงกลมโตออกจากปุ่มที่กดจริง** รัศมีต้องถึงมุมที่ไกลที่สุด (`Math.hypot`) ไม่งั้นเหลือธีมเก่าค้างมุมจอ

**ห้าม crossfade** — fade สองธีมพร้อมกันลากทั้งคู่ผ่านเทากลางเดียวกัน (วัดแล้ว contrast ตก 16.8 → 1.1 → 16.8) อ่านเป็นตัวหนังสือกะพริบหาย wipe ไม่เคยผสมสองธีม ทุกพิกเซลอยู่ที่ contrast เต็มทั้งสองฝั่งของขอบที่วิ่ง

**ห้ามใช้ View Transitions API** — Safari snapshot จากบนสุดของ document ทำให้หน้าเด้งไปบนสุดตลอดช่วง wipe แล้วเด้งกลับทุกครั้งที่กด
ให้วาดเองบน overlay element เดียว: วงกลมบานคลุมหน้าด้วยสีพื้นของธีมใหม่ → สลับธีมข้างใต้ตอนมองไม่เห็น → fade overlay ออก (160ms) เนื้อหาข้างใต้ถูกต้องอยู่แล้วเลยไม่มีอะไร pop
**WAAPI promise ไม่ settle ใน background tab** → ต้องมี `setTimeout` เก็บกวาด overlay สำรองเสมอ

## 4. กฎที่ห้ามข้าม

- **contrast ต้องวัด ไม่ใช่เดา** แล้ว**เขียนตัวเลขที่วัดได้ไว้ใน comment** ตรงนั้น (เช่น "L .58 วัดได้ 4.24:1 กับหมึกที่พิมพ์ทับ → ขยับเป็น L .62 = 5.01:1") คนที่มาอ่านทีหลังจะได้ไม่ปรับกลับ
- ทุกตัวเลขที่ดู "มั่ว" แต่ถูก (margin ลบตาม font metric, `27.4vw`) ต้องมี comment บอกว่า**วัดมาจากอะไร** ไม่งั้นรอบหน้าโดนลบทิ้ง
- comment เขียนว่า **"ทำไม" ไม่ใช่ "อะไร"** โดยเฉพาะจุดที่เคยพังแล้วแก้
- โฟกัสมองเห็นได้ทุก interactive element, ทุกรูปมี alt, section มี `aria-labelledby`
- ฟอร์ม: honeypot + สถานะ loading/success/error จริง + ข้อความ privacy ใต้ปุ่ม
- มือถือ: order bar ลอยล่างที่โผล่เมื่อ hero พ้นจอ และ**ซ่อนเมื่อถึงฟอร์ม** (ไม่ทับสิ่งที่ตัวเองชี้ไป)
- ไม่มีอะไรกระโดดตอนโหลด: ฟอนต์ `display=swap` + preconnect, รูปมี width/height

## 4b. กับดักที่เหยียบมาแล้ว (เพิ่มทุกครั้งที่เจอของใหม่)

- **emoji เคลื่อนไหวของ Noto บางตัว "เคลื่อนที่ผ่านเฟรม" — ไม่ใช่ของเสีย แต่ถ่ายภาพนิ่งไม่ได้ตามใจ** โลมา 1f42c · มังกร 1f409 · ฉลาม 1f988 ออกแบบให้ตัวมันว่าย/บินเข้าออกกรอบ เฟรมแรกจึงว่างเปล่าสนิท (วัด 21/8/26: วาดเฟรมแรกลง canvas นับพิกเซลไม่โปร่งใสได้ 0 เทียบกับ png นิ่งที่ .42) **ในแอปจริงไม่มีปัญหา** คนเห็นอนิเมชันวนครบรอบ ปัญหาเกิดเฉพาะตอนแช่แข็งเป็นภาพนิ่ง — ijek-3.webp รอบแรกถ่ายติดจังหวะที่โลมาอยู่นอกกรอบ เหลือแค่ครีบ (jek ทักเอง) วิธีถ่าย: เก็บหลายเฟรมห่างกัน ~130ms แล้วเลือกเฟรมที่ "หมึกเยอะสุด" ในกรอบนั้น (ครอปกรอบมาชั่งขนาดไฟล์ PNG ก็พอ พื้นหลังเรียบสีเดียว ไฟล์ใหญ่กว่า = มีตัวสัตว์อยู่ในกรอบมากกว่า) **อย่าไปแก้แอปหรือเลี่ยง emoji ตัวนั้น** — สิ่งที่ผิดคือจังหวะกดชัตเตอร์ ไม่ใช่ตัวอาร์ต
- **กฎที่ไม่มีเครื่องจับคือกฎที่ถูกข้าม** — §1b ข้อ 1 (reference pass) เขียนไว้ตั้งแต่ต้นพร้อมบันทึกว่าเคยพลาดมาแล้ว แล้วก็ยังพลาดซ้ำอีกสามหน้าโดยไม่มีใครรู้จนเจ้าของเว็บเห็นเอง (และตอนแรกเครื่องจับที่เขียนขึ้นก็วัดผิดจุด — ไปวัดฮีโร่ซึ่งซ้ำได้ ต้องรื้อมาวัดข้างในแทน เครื่องตรวจที่รายงานของที่ไม่ใช่ข้อผิด สอนให้คนเลิกอ่านผลของมัน) เวลาจะเพิ่มกฎใหม่ลงไฟล์นี้ ให้ถามก่อนว่า "อะไรจะเป็นตัวจับว่ากฎนี้ถูกข้าม" ถ้าตอบไม่ได้ กฎนั้นจะอยู่ได้แค่ในกระดาษ — เขียนเครื่องตรวจคู่กันเสมอ (`audit-sameness.mjs` เกิดจากบทเรียนข้อนี้)
- **`radial-gradient` นับ 100% เป็น farthest-corner ไม่ใช่ขอบวงกลม** — mask วงแหวนที่เขียน `radial-gradient(circle, transparent 0 84%, #000 84%)` จะไปตกนอกวงกลมแล้วโดน `overflow:hidden` ตัดหายทั้งวง ต้องระบุ `closest-side` ทุกครั้งที่ mask ของกลม
- **แถบเข้ม (`section--ink`) ในธีมมืดต้อง "ยกขึ้น" ไม่ใช่ "กดลง"** — ค่าที่ใช้ในธีมสว่างมักไปตรงกับ `--color-bg-subtle` ของธีมมืดพอดี แถบเลยกลืนหายไปเฉยๆ และให้คุมด้วย**ตัวแปรเดียว** (`--ink-plate`) ที่ใช้ทั้งพื้นแถบและกล่องเล็กๆ ที่ทับอยู่บนแถบ ไม่งั้นกล่องพวกนั้นจะลอยเป็นแผ่นสีเก่า
- **คำปิดท้ายที่มีหางล่าง (y, g, ฎ, ฐ) หรือเส้นทับ (/) ห้ามตัด margin ล่างติดลบ** — สูตรที่ใช้กับคำตัวพิมพ์ใหญ่ล้วนได้ พอมีหางแล้วหางขาดทันที ให้ไปตัดอากาศ**ด้านบน**แทน และเผื่อ padding ล่างไว้เป็นพื้น
- **ท่า wipe ต้องเลื่อนเกิน 100%** ถ้ากล่องมี padding — `overflow` ตัดที่ขอบ padding-box ซึ่งสูงกว่าตัวอักษร เลื่อน 100% เป๊ะจะเหลือหัวตัวอักษรโผล่ค้าง ใช้ 120%
- **ห้ามใส่คลาสคอนเทนเนอร์ (`.wrap`/`.container`) ร่วม element เดียวกับคลาสที่กำหนด `max-width` แคบกว่า** — คอนเทนเนอร์มี `margin-inline:auto` พอ max-width แคบกว่าเข้ามาทับ บล็อกจะลอยไปกลางจอแทนที่จะชิดขอบซ้ายเหมือน section อื่น อาการคือ "ข้อความก้อนนี้ไม่ตรงกับใครเลย" ให้ซ้อนเป็น `<div class="wrap"><div class="narrow">` เสมอ (พลาดมาแล้ว 2 งานติด)
- **ฟอนต์ display ที่ไม่มีตัวไทย (Anton, Bebas, Oswald ฯลฯ) = พาดหัวไทยตกไปใช้ฟอนต์เนื้อความ** แล้วอ่านเป็นข้อความธรรมดา ไม่ใช่พาดหัว ถ้าอยากได้บุคลิกละตินตัวนั้นจริงๆ ให้แยกเป็นสองตัวแปร: ตัวไทยที่หนักได้จริง (Kanit/Anuphan/Noto Sans Thai 800) กับตัวละตินไว้เฉพาะ wordmark
- **รูปประกอบต้องเลือกจาก "ฉากหลังเข้ากับพื้นหน้าเว็บ" ก่อนความสวย** — หน้าพื้นดำเอารูปพื้นสว่างมาวางได้สี่เหลี่ยมแปะกลางจอ เลือกรูปที่ฉากหลังมืดอยู่แล้ว + `mask-image: radial-gradient(...)` ให้ขอบจางหายไปในพื้น และครอบสัดส่วนตั้งแต่ตอนเตรียมไฟล์ ไม่ใช่ครอบด้วย CSS (รูป 2:3 กลางหน้าดัน CTA ตกขอบจอได้ง่ายๆ)
- **ของที่หน้าตาเป็นปุ่มต้องกดได้จริง** — ชิป/pill ที่เป็น `<li>` เปล่าๆ แต่แต่ง border+radius ไว้ คือหลอกตา ถ้ากดไม่ได้ก็อย่าแต่งให้เหมือนปุ่ม
- **ใส่ test hook ไว้ตั้งแต่ต้น: `?theme=light|dark` และ `?reduce=1`** — สลับธีมและจำลอง reduced-motion จาก URL ได้เลย ทำให้ถ่ายรูปเทียบสองธีมและตรวจ "start state ถูกเคลียร์จริงไหม" ได้โดยไม่ต้องแตะ setting เครื่อง (และเป็นทางเดียวที่ headless ถ่ายส่วนล่างของหน้าได้ เพราะ IntersectionObserver ไม่ยิงใน virtual time)
- **ตรวจงานด้วย headless Chrome ได้ ไม่ต้องรอเปิดเบราว์เซอร์เอง**
  `"/Applications/Google Chrome.app/Contents/MacOS/Google Chrome" --headless=new --disable-gpu --hide-scrollbars --virtual-time-budget=9000 --window-size=1440,7400 --screenshot=out.png "URL?reduce=1"`
  แล้ว crop ด้วย PIL เป็นช่วงๆ เพื่อดูให้ชัด (`Image.open(...).crop((0,y1,w,y2))`)

## 5. ลำดับทำงาน (ห้ามลัด)

   เปิดแค่ ENGINE + BRIEF แล้วได้ของที่ผ่านด่านทุกด่านทั้งที่ละเมิดกฎอยู่หลายข้อ มาแล้วสองครั้ง
   (chang-chat 22 ส.ค. · dr-delight 24 ส.ค. 2026)
