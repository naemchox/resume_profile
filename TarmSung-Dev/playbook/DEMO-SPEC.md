## S1 — หน้าและข้อมูล

**แกน: โครงหน้ามาจากของที่ลูกค้ามีจริง ไม่ใช่จากลิสต์ section มาตรฐาน**

### S1.0 reference ที่เจ้าของส่งมา — รับเข้าก่อน แล้วค่อยออกแบบ
เจ้าของส่งภาพจาก Pinterest / เว็บอื่นมาให้ = **วัตถุดิบของงานนี้ ไม่ใช่ความเห็นผ่านๆ**
ต้องมีที่อยู่ ไม่ใช่ค้างในแชท

- เก็บไฟล์/ลิงก์ไว้ที่ `<โปรเจกต์>/_ref/inspo/` แล้วเขียนลง `INVENTORY.md` หัวข้อ **reference**
- แต่ละใบต้องเขียน 1 บรรทัดว่า **"เอาอะไรจากใบนี้"** — พาเลตต์ · ระยะห่าง · ทรงหัวข้อ · จังหวะเข้าฉาก
  ใบที่เขียนไม่ได้ว่าจะเอาอะไร = ยังไม่ใช่ reference มันคือรูปที่ชอบเฉยๆ
- **เอาสไตล์ ไม่เอาองค์ประกอบ** — ลอกพาเลตต์/อารมณ์/รายละเอียดได้ แต่ลำดับ section กับเนื้อหา
  ต้อง derive จากธุรกิจลูกค้าเอง (ลอกทั้งหน้า = เว็บลูกค้ากลายเป็นเว็บคนอื่นที่เปลี่ยนโลโก้)
- reference ของเจ้าของ **ไม่แทน** reference pass ของ CHECKLIST ด่าน 0 (เปิดเว็บที่ดีที่สุด 3 เจ้าในหมวดเดียวกัน)
  สองอันคนละหน้าที่: ของเจ้าของบอก "อยากได้อารมณ์ไหน" · reference pass บอก "หมวดนี้เขาใช้เครื่องมืออะไร"

**เครื่องจับ:** `INVENTORY.md` ต้องมีหัวข้อ `## reference` และทุกใบใน `_ref/inspo/` ต้องถูกเอ่ยถึง
→ `node playbook/audit-pages.mjs --inv <INVENTORY.md> --demo <โฟลเดอร์>`

### S1.1 ของเก่าลูกค้า — ทำก่อนเขียนโค้ดบรรทัดแรก
ลูกค้ามีเว็บเก่า / เพจ / รูป → ทำ inventory ลงตารางก่อน: ทุกหน้า · ทุก section · ทุกรูป
แต่ละแถวต้องเขียนว่าไปอยู่ตรงไหนของเว็บใหม่

**ขั้นแรกสุดคือนับหน้า: เว็บเก่าเป็นหน้าเดียวหรือหลายหน้า**
- เว็บเก่าเป็น **หลายหน้า** → เว็บใหม่ต้องมี **ครบทุกหน้า** ไล่จาก sitemap/เมนูของเขาเอง
  งานเราคือ**อัปเกรดดีไซน์ให้ดีขึ้น ไม่ใช่ย่อเว็บเขาให้เล็กลง** — ลูกค้าที่มี 8 หน้าแล้วได้เว็บใหม่ 1 หน้า
  คือลูกค้าที่เสียของ ต่อให้หน้าเดียวนั้นสวยกว่าก็ตาม
- หน้าไหนจะยุบรวมกับหน้าอื่นได้ ต้อง**เขียนกำกับว่ายุบเข้าไปอยู่ที่ไหน** ไม่ใช่หายไปเฉยๆ
- เว็บเก่าเป็น **หน้าเดียว** → เว็บใหม่เป็นหน้าเดียวได้ แต่ทุก section ของเขาต้องมีที่อยู่
- ตัดสินเรื่องนี้ **ก่อน**เลือกแพ็กเกจ ไม่ใช่หลัง — เว็บเก่า 8 หน้าแล้วเสนอแพ็กหน้าเดียว = เสนอผิดตั้งแต่ต้น

**เครื่องจับ:** `node playbook/audit-pages.mjs --inv <INVENTORY.md> --demo <โฟลเดอร์>`
(ทุกหน้าที่ตารางบอกว่า "ต้องมี" ต้องมีไฟล์จริง และต้องมีลิงก์จากเมนูไปถึง)

- **ของลูกค้าหายโดยไม่มีเหตุผลเขียนกำกับ = ตก** — "ตัดเพราะหน้าสวยกว่า" ไม่ใช่เหตุผล
- **รูปที่ลูกค้าให้มาต้องถูกใช้ทุกใบ** หรือมีบรรทัดบอกว่าทำไมไม่ใช้
- **ห้ามส่งงานที่มีกรอบ placeholder ว่างโชว์อยู่** — ไม่มีของ = ตัด section นั้นทิ้ง ไม่ใช่ปล่อยกรอบเปล่า
- แหล่งรูปเมื่อลูกค้าไม่มีของ → `LOG-DEMO.md §12` (ห้าม hotlink · ห้ามงานออกแบบของคนอื่น · ต้องเปิดดูทุกใบ)

> เคสที่ทำให้ตั้งข้อนี้ — dr-delight: รูปจริงของคลินิก 4 ใบนอนอยู่ใน `_ref/promo-full/` ไม่ถูกใช้เลย
> หน้าใช้รูปเครื่องมือ/นางแบบทั่วไปแทน และเหลือกรอบ `.slot` ว่างโชว์อยู่ในส่วนผลลัพธ์

**เครื่องจับ:** `node playbook/audit-assets.mjs --ref <โฟลเดอร์ของลูกค้า> --demo <index.html>`
เทียบว่ารูปที่ลูกค้าให้ถูกใช้ครบไหม + หากรอบ placeholder ว่างที่ยังโชว์อยู่ในหน้า
(เทียบด้วย**ชื่อไฟล์** รูปที่ถูกเปลี่ยนชื่อจะหลุดด่านนี้ — เปลี่ยนชื่อแล้วต้องเขียนกำกับไว้)
ส่วนเนื้อหาที่หายเทียบกับรอบก่อน ใช้ `node playbook/regress.mjs --live` (มีแค่ `--live` / `--base <ref>`)

### S1.2 ห้าม section มาตรฐาน
ทุก section ต้องตอบได้ว่า "ลูกค้ารายนี้มีของอะไรมาลง" ไม่มีของจริง = ไม่มี section นั้น
ห้ามใส่เพราะเดโมใบอื่นมี — นี่คือรากของ "หน้านี้ต้องรีวิว หน้านี้ต้องแมพ"

ที่มีอยู่แล้ว ใช้ต่อ ไม่เขียนซ้ำ:
- จำนวนช่อง 4 หรือ 6–7 ตามชนิดธุรกิจ เกิน 7 ต้องมีเหตุผลกำกับ → `PROMPT-BLOCKS.md`
- derive ลำดับใหม่ทุกครั้ง ต้องต่างจากงานล่าสุด ≥2 จุดเชิงโครงสร้าง → `BRIEF-TEMPLATE.md` B3.5
- ข้อมูลคนละชนิดใช้เครื่องมือคนละอย่าง (ลิสต์ราคา ≠ การ์ด · ลำดับเวลา ≠ กริด) → `ENGINE.md §1b.4b`

**เครื่องจับ:** `node playbook/audit-sameness.mjs` (Jaccard คำศัพท์คลาสใต้ hero ข้ามโปรเจกต์ FAIL ที่ 0.50)

### S1.4 หน้าเดียวห้ามซ้ำตัวเอง (ย้ายมาจาก website.md §11)
1. **ทรงหัวข้อไม่เกิน 3 แบบ** และห้ามใช้แบบเดียวรวดทั้งหน้า · ทรงเดียวกันติดกันเกิน 2 ส่วน = ตก
2. **ของตกแต่งประจำแบรนด์ (เส้นหยัก/ขีด/ไอคอน) ไม่เกิน 3 จุดต่อหน้า** — ใส่ทุกส่วน = กลายเป็นวอลเปเปอร์
3. **พื้นหลังเปลี่ยนอย่างน้อย 3 ครั้งตลอดหน้า** (สว่าง → ทึบ → ภาพ/เฉด) ให้ตาแบ่งบทได้
4. **รูปทรงของ block ห้ามซ้ำเกิน 2 ครั้งในหน้าเดียว** → `ENGINE.md §1b.4`

## S2 — แอนิเมชัน (smooth ทุกจุด ไม่กระตุก ไม่แวบ)

### S2.1 หนึ่ง element = หนึ่งตัวขับ
ห้าม CSS `animation` กับ JS `style.transform` ทำงานทับ element เดียวกัน
> the-bed: `heroSettle` scale 1.06→1 ยาว 2,800ms (`:528`) + parallax เขียน transform ทุกเฟรม (`:1459`)
> ลงบนแผ่นเดียวกัน → ทั้ง hero รวมหัวข้อสั่นตลอด 2.8 วินาทีแรก **นี่คือ headline กระตุกที่เห็น**

### S2.2 ฟอนต์ต้องนิ่งก่อน แล้วค่อยเล่นตัวอักษร
หัวข้อที่มี animation ต้อง `preload` ฟอนต์ + เริ่มเล่นหลัง `document.fonts.ready`
> the-bed โหลดฟอนต์ `display=optional` สลับที่ ~427ms ขณะที่ word-reveal วิ่ง 750ms + stagger 180ms
> และแต่ละคำอยู่ในกล่อง `overflow:hidden` ที่ขนาดเปลี่ยนตามฟอนต์ = กล่องหดขยายใต้ตัวอักษรที่กำลังวิ่ง

### S2.3 รันบน compositor เท่านั้น
`transform` · `opacity` · `clip-path` เท่านั้น ห้ามอนิเมต layout property (`top`/`left`/`width`/`height`)

### S2.4 ห้ามอนิเมต `filter` / `backdrop-filter`
`drop-shadow` ใน keyframes = 30fps ตลอดเวลา (velvet-leaf) · transition blur ตอนเลื่อน = re-blur ทุกเฟรม
(the-bed `:325` ยิงตอน `scrollY>40` ซึ่งทับกับช่วงที่หัวข้อยังวิ่งอยู่พอดี) → **toggle ทันที ไม่ transition**

### S2.5 ห้าม fade / scale แผ่นใหญ่เต็ม viewport
ต่อจาก `ENGINE.md §2` "ของใหญ่ห้าม fade" — the-terrace: ชั้น `inset:0` 978k px² บังคับ repaint
รูป hero 1,524k px² ทุกเฟรม

### S2.6 `will-change` เปิดเฉพาะช่วงเล่น แล้วปลดทิ้ง
ห้ามค้างไว้ทุก section และห้ามลืมใส่ให้ของที่เล่นจริง
> the-bed: `.reveal` `.marquee` `.zoom-img` `.hero-layer` มีครบ แต่ `.split .wi` (คำในหัวข้อ) ไม่มีเลย

### S2.7 ห้ามอ่าน layout ใน scroll frame ระหว่างยังมี animation ค้าง
`getBoundingClientRect()` ใน rAF ทุกเฟรม = forced layout
> the-bed `sweep()` (`:1577`) เป็นตาข่ายกันพลาดของ IntersectionObserver แต่มันวิ่งทับช่วง transition ของหัวข้อ

### S2.8 ภาพห้ามแวบ
- ทุก `<img>` มี `width`/`height` (กัน layout กระโดด)
- รูปครึ่งจอแรก `eager` + `preload` · ที่เหลือ `lazy`
- fade รูปเข้าได้ต่อเมื่อ `decode()` เสร็จแล้วเท่านั้น ห้าม fade จาก 0 ขณะไฟล์ยังโหลด

### S2.9 hover ต้องมีจริงและเปลี่ยนมากกว่าหนึ่งอย่าง (ย้ายมาจาก website.md §13)
- ของที่ "กดได้หรือเป็นการ์ด" ต้องมี hover ทุกชิ้น · **`:hover` ต่ำกว่า 15 จุดต่อหน้า = ยังไม่ผ่าน**
- hover ที่ดีเปลี่ยน 3 อย่างพร้อมกัน (ยก + เงา + ขอบ) และลามถึงลูกข้างใน (รูปซูม · ราคาเปลี่ยนสี)
- ครอบทั้งชุดด้วย `@media (hover: hover)` — บนมือถือ `:hover` ค้างหลังแตะ
- ห้ามใช้ `transform` ใน `:hover` กับ element ที่มี `animation … both` ค้างอยู่ (คีย์เฟรมสุดท้ายชนะเสมอ)

### S2.10 การเลื่อนต้องมีมากกว่าสวิตช์เปิด/ปิด
อย่างน้อย 1 อย่างที่ขยับตาม **ตำแหน่ง** การเลื่อน (parallax · แถบความคืบหน้าการอ่าน · ของลอยตามจอ)
และอย่างน้อย 3 ส่วนต้องมีเอฟเฟกต์เข้าฉากเฉพาะตัว ห้ามทั้งหน้าใช้ `.reveal` ตัวเดียวกันหมด
ทุกอย่างต้องอยู่ใน rAF + scroll listener **ตัวเดียวกัน** และ `{passive:true}`

### S2.11 แถบนำทางตอบสนองการเลื่อน
หดลงตอนเลื่อน + ไฮไลต์หัวข้อที่กำลังอ่าน (หน้าเดียว = scroll-spy · หลายหน้า = `aria-current="page"`)
กลไกร่วม: `js/nav-response.js` — ก๊อปไฟล์เดิม ห้ามเขียนใหม่รายชิ้น

### S2.12 ปิดทุกอย่างเมื่อ `prefers-reduced-motion`
รวมถึงสวิตช์ `?reduce=1` ที่สคริปต์ถ่ายภาพใช้
