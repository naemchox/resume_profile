Anatomy

Three passes.
No scene graph.

A Lumen preset is one fragment shader over two triangles. There is no camera, no mesh, no render loop you own — which is why the runtime fits in 9.4 kb.

Adaptive resolution

The runtime measures its own frame cost and drops the buffer scale before it drops frames. On a throttled phone that lands at 0.65× — visually identical under a blur-heavy preset.

Nothing off-screen

Every instance carries an IntersectionObserver and a visibility listener. Scroll a preset out of view and its loop stops on the next frame — not on a timer.

Reduced motion is a state

Under prefers-reduced-motion a preset renders one frame and holds it. You still get the artwork; it just stops moving.

Quickstart

Installed and shipping

Same three steps in every stack. No build plugin, no shader files to copy, no canvas ref to babysit.

Questions

The ones we actually get.

Every preset ships a CSS gradient fallback derived from the same three-colour ramp. If the context fails to create, the gradient stays and nothing throws — that is what this page does in the hero.
The draw call does, the work does not — everything expensive is in the fragment shader on the GPU. Per-frame JS is one uniform update and one drawArrays.
Pass a three-colour ramp and the preset re-tunes around it. In Pro the editor exports that ramp as tokens, so a brand change is a token change and not a shader rewrite.
Browsers cap live WebGL contexts around sixteen. Lumen keeps a pool: instances off-screen release their context and get it back on the way in. The gallery above is six at once and one in the hero.
Per developer. Ship it on as many client sites as you like; the projects are not counted, the seats are.
