# ติดตั้งระบบให้ลูกค้ารายใหม่

ระบบนี้เป็นแบบ **1 ลูกค้า = 1 ชุด** ข้อมูลของแต่ละบริษัทแยกขาดจากกันคนละฐานข้อมูล

---

## 1. สร้าง Supabase project ใหม่

สร้างโปรเจกต์ใหม่ต่อลูกค้า 1 ราย **ห้ามเอาโปรเจกต์ของลูกค้ารายอื่นมาใช้ซ้ำ**
เลือก region ที่ใกล้ลูกค้าที่สุด (สิงคโปร์สำหรับลูกค้าไทย)

จดค่าไว้ 2 ตัวจากหน้า Project Settings → API:
- Project URL
- `anon` public key

## 2. รัน SQL ตามลำดับ

เปิด SQL Editor ใน Supabase แล้ววางทีละไฟล์ **ต้องเรียงตามนี้เท่านั้น**

| ลำดับ | ไฟล์ | ทำอะไร |
|---|---|---|
| 1 | `db/01_schema.sql` | ตารางทั้งหมด |
| 2 | `db/02_views.sql` | ตัวเลขที่คำนวณเอา (ยอดเทียบราคา · งบคงเหลือ · ประวัติผู้ขาย) |
| 3 | `db/03_rls.sql` | กติกาว่าใครเห็นอะไรได้ |
| 4 | `db/04_functions.sql` | กติกาว่าใครทำอะไรได้ |
| 5 | `db/05_triggers.sql` | ประวัติการใช้งาน + กติกาแยกหน้าที่ + เลขที่เอกสาร |
| 6 | `db/06_seed.sql` | ค่าตั้งต้น (SOW 6 ข้อ · อัตราภาษี · วงเงินอนุมัติ) |
| 7 | `db/07_invites.sql` | คำเชิญผู้ใช้ (เจาะจงอีเมล · ลิงก์เชิญ) |
| 8 | `db/08_remove_user.sql` | ลบผู้ใช้ออกจากระบบ |

## 3. ตรวจว่ากติกาทำงานจริง

```
psql "$DATABASE_URL" -f db/tests.sql
```

ต้องได้ **ผ่านทุกข้อ** ถ้ามีข้อไหนตก แปลว่ามีรูให้โกง **ห้ามส่งมอบ**

ชุดทดสอบจะสร้างข้อมูลตัวอย่างทิ้งไว้ ให้ลบก่อนใช้งานจริง:

```sql
delete from auth.users where email like '%@t.local';
```

## 4. ตั้งค่าหน้าเว็บ

```
cp js/config.example.js js/config.js
```

แล้วใส่ Project URL กับ anon key ที่จดไว้จากข้อ 1
(`js/config.js` อยู่ใน .gitignore แล้ว)

## 5. สร้างผู้ดูแลระบบคนแรก

1. ใน Supabase → Authentication → Users → สร้างผู้ใช้คนแรกด้วยอีเมลของลูกค้า
2. เปิดหน้าเว็บ เข้าสู่ระบบด้วยบัญชีนั้น
3. ระบบจะบอกว่ายังไม่มีตำแหน่ง และขึ้นปุ่ม **"ตั้งตัวเองเป็นผู้ดูแลระบบคนแรก"**
4. กดปุ่มนั้น

ปุ่มนี้ใช้ได้ครั้งเดียว พอมีผู้ดูแลแล้วจะกดไม่ได้อีก และไม่มีใครตั้งตำแหน่งให้ตัวเองได้อีกเลย

## 6. เพิ่มผู้ใช้คนอื่น

ผู้ดูแลระบบ → **ตั้งค่าระบบ → ผู้ใช้และตำแหน่ง → ปุ่ม “+ เพิ่มผู้ใช้”** มี 2 แบบ

| แบบ | ใช้เมื่อไหร่ | ข้อจำกัด |
|---|---|---|
| เจาะจงอีเมล | รู้อีเมล Google ของคนนั้นแน่นอน | ใช้ได้ครั้งเดียว และเฉพาะคนที่ล็อกอินด้วยอีเมลนั้น |
| ลิงก์เชิญ | ให้หัวหน้าแผนกกระจายต่อเอง | ใครถือลิงก์ก็เข้าได้ — จำกัดด้วยจำนวนครั้ง + วันหมดอายุ |

ติ๊ก **ไม่มีวันหมดอายุ** ได้ถ้าไม่อยากให้คำเชิญตายเอง (ยกเลิกเองได้ตลอดจากปุ่มยกเลิกในตาราง)

คำเชิญที่ยังไม่ถูกใช้ กดปุ่ม **แก้ไข** ในตารางคำเชิญเพื่อเปลี่ยนวันหมดอายุ · ตำแหน่ง · ชื่อ · จำนวนครั้ง ได้
(อีเมลกับลิงก์ไม่เปลี่ยน ลิงก์ที่ส่งไปแล้วยังใช้ได้) ส่วนปุ่ม **แก้ไข** ในตารางผู้ใช้ ใช้แก้ชื่อ · รหัสพนักงาน · ตำแหน่งงาน · แผนก

ทั้งสองแบบตั้งตำแหน่งล่วงหน้าได้ ระบบจะผูกตำแหน่งให้อัตโนมัติตอนคนนั้นล็อกอิน Google ครั้งแรก

**ระบบไม่ได้ส่งอีเมลเอง** (ไม่มี mail service ในชุดนี้) — หลังสร้างคำเชิญจะได้ลิงก์มาให้
กด “คัดลอกลิงก์” หรือ “ส่งทางอีเมล” (เปิดโปรแกรมอีเมลพร้อมข้อความให้แล้ว) แล้วส่งเอง

กติกาที่ยังบังคับอยู่เหมือนเดิม: สร้างคำเชิญให้อีเมลของตัวเองไม่ได้ และใช้คำเชิญที่ตัวเองสร้างไม่ได้

## 7. ลบผู้ใช้ออกจากระบบ

ปุ่ม **ลบ** ท้ายแถวในตารางผู้ใช้ (ไม่มีให้ในแถวของตัวเอง) ผลลัพธ์ขึ้นกับว่าคนนั้นเคยทำเอกสารไว้ไหม

| กรณี | เกิดอะไรขึ้น |
|---|---|
| ไม่เคยแตะเอกสารเลย (เชิญผิดคน) | ลบแถวผู้ใช้ทิ้งจริง เชิญใหม่ด้วยอีเมลเดิมได้ |
| เคยทำเอกสาร | ลบถาวรไม่ได้ — ประวัติจัดซื้อผูกกับคนทำไว้ 24 จุด ระบบจะถอนตำแหน่งทั้งหมด + ปิดบัญชีแทน |

ทั้งสองกรณี: เข้าระบบไม่ได้อีก · คำเชิญที่ค้างของเขาและที่เขาเป็นคนออกถูกยกเลิกทั้งหมด · มีบันทึกใน `audit_log`

ลบผู้ดูแลระบบคนสุดท้ายไม่ได้ และลบบัญชีตัวเองไม่ได้

บัญชีใน Supabase Auth ยังอยู่ (ลบจากเบราว์เซอร์ไม่ได้ ต้องใช้ service key) ถ้าอยากลบให้หมดจริง
ไปที่ Dashboard → Authentication → Users อีกที — แต่ไม่ลบก็เข้าระบบไม่ได้อยู่ดี

## 6. ผู้ดูแลตั้งค่าที่เหลือ

เข้าหน้า **ตั้งค่าระบบ** แล้วกรอกตามลำดับ:

1. **ข้อมูลบริษัท** — ชื่อ เลขผู้เสียภาษี ที่อยู่ โลโก้ เดือนที่เริ่มปีงบ
2. **ผู้ใช้และตำแหน่ง** — เชิญพนักงานเข้าระบบ แล้วตั้งตำแหน่งให้
3. **วงเงินอนุมัติ** — ค่าตั้งต้นคือ ENG ≤ 50,000 · PM ≤ 300,000 · PD ≤ 1,000,000 · CEO ไม่จำกัด
4. **ศูนย์ต้นทุน / โครงการ / งบประมาณ** — ลบศูนย์ต้นทุนตัวอย่างทิ้งได้
5. **ทะเบียนผู้ขาย**
6. **Scope of Work** — 6 ข้อตั้งต้น แก้ถ้อยคำให้ตรงกับธุรกิจลูกค้าได้
7. **อัตราภาษีหัก ณ ที่จ่าย** — ตรวจว่าตรงกับที่บัญชีลูกค้าใช้

## 7. เปิดหน้าเว็บ

ไม่ต้อง build ไม่ต้องติดตั้งอะไร เปิดไฟล์ `index.html` ด้วย Live Server หรือวางทั้งโฟลเดอร์ไว้บนโฮสต์ไฟล์นิ่งอะไรก็ได้

ไลบรารีทั้งหมดอยู่ใน `js/vendor/` แล้ว **ระบบไม่เรียก CDN ตอนใช้งาน** เครื่องลูกค้าที่ล็อกเน็ตขาออกก็ใช้ได้ ขอแค่ต่อ Supabase ได้

## ตำแหน่งงานในระบบ

| ตำแหน่ง | ทำอะไรได้ |
|---|---|
| ผู้ขอซื้อ | ตั้งเรื่องขอซื้อ กรอก Scope of Work |
| ฝ่ายจัดซื้อ | ออกใบขอราคา คีย์ใบเสนอราคา ให้คะแนน เลือกผู้ชนะ ออก PO บันทึกส่งมอบ คีย์ใบแจ้งหนี้ |
| ผู้ตรวจรับ (ENG) | ตรวจรับงาน · ยืนยันครบระยะรับประกัน · เป็นขั้นแรกของสายอนุมัติ |
| PM / PD / CEO | อนุมัติตามวงเงิน (CEO อนุมัติการขอยกเว้นงบด้วย) |
| บัญชี | ตั้งงบ อนุมัติจ่าย จ่ายเงินจริง คืนเงินประกัน |
| ผู้ดูแลระบบ | ตั้งค่าทุกอย่าง ตั้งตำแหน่งให้คนอื่น (ตั้งให้ตัวเองไม่ได้) |

## กติกาที่ระบบบังคับตลอดเวลา — บอกลูกค้าได้เลย

- คนคีย์ใบเสนอราคา อนุมัติเรื่องนั้นไม่ได้
- ผู้ขอซื้อ อนุมัติเรื่องของตัวเองไม่ได้
- คนบันทึกส่งมอบ ตรวจรับเองไม่ได้
- คนคีย์ใบแจ้งหนี้ กดอนุมัติจ่ายเองไม่ได้
- คนยืนยันครบระยะรับประกัน คืนเงินประกันเองไม่ได้
- ไม่มีใครตั้งตำแหน่งให้ตัวเองได้ แม้แต่ผู้ดูแลระบบ
- ประวัติการใช้งานลบไม่ได้ แก้ไม่ได้ ไม่มีข้อยกเว้น
- สั่งซื้อเกินงบไม่ได้ จนกว่า CEO จะอนุมัติยกเว้น
- ใบแจ้งหนี้ที่จับคู่ PO ↔ ใบรับของ ไม่ตรง ตั้งเบิกไม่ได้
- ผู้ขายที่รับเงื่อนไข Scope of Work ไม่ครบ ถูกตัดออกจากการพิจารณาอัตโนมัติ
