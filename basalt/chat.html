How this chat works

This is a frontend-only app. There is no server code behind it. It connects to Basalt with a public config, and every read, write, and live update goes straight to the database — with your rules deciding what's allowed.

1 · Connect with a publishable config


      

        The publishable key is safe to ship in client code — like Firebase's
        apiKey. It identifies the project; it grants no power on its own.
      


      
2 · The rules decide what's allowed

      
-- everyone signed in can read messages…
create policy "messages are readable" on messages
  for select to authenticated using (true);

-- …but you may only post AS YOURSELF
create policy "post as yourself" on messages
  for insert to authenticated
  with check (author_id = auth.uid()
              and author_email = auth.email());

      

        These live in the database, set once by the provider. Try editing a message's
        author_id in the code — the insert is rejected server-side.
      


      
3 · Send data → it's stored → everyone sees it live

      
// post a message — this is the entire "backend call"
await basalt.from('messages').insert({
  room_id: 'general', body: text,
  author_id: user.id, author_email: user.email,
});

// and subscribe to new ones as they arrive
basalt.channel('msgs:general')
  .on('postgres_changes',
      { table: 'messages', event: 'INSERT' },
      (e) => render(e.new))
  .subscribe();
