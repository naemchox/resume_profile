## Git Workflow

After completing any meaningful unit of work — a feature, a fix, a refactor, or a logical stopping point — commit the changes and push to GitHub. Never let work accumulate uncommitted.

- **Commit often:** Each commit should represent one coherent change. Do not bundle unrelated changes into a single commit.
- **Clean commit messages:** Use the imperative mood, present tense (e.g. `Add user authentication`, not `Added` or `Adding`). Keep the subject line under 72 characters. If more context is needed, add a blank line followed by a short body.
- **Push after every commit:** Run `git push` immediately after committing so work is backed up on GitHub and visible to collaborators.
- **Never leave work uncommitted at the end of a session:** If a task is mid-flight, commit with a `wip:` prefix (e.g. `wip: implement login flow`) so progress is not lost.
